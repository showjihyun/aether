# Harness Score

| 소유자 | 재검토 조건 |
| --- | --- |
| unassigned | 채점 축이 바뀔 때, `HE-*` 인벤토리가 바뀔 때, 또는 두 번째 채점 라운드에서 축이 변별하지 못하는 것이 드러날 때 |

이 스킬은 "하네스가 있느냐"가 아니라 **"하네스의 어느 부분이 얼마나 약하냐"**를 답할 때 읽습니다. 성숙도 단계(L0~L5)는 저장소 하나에 값 하나를 주므로 다음에 무엇을 고칠지 알려주지 못합니다. 이 스킬은 요소 15개마다 여섯 축의 점수를 매겨 **가장 싸게 가장 많이 오르는 자리**를 지목합니다.

## 다른 절차와의 경계

| 무엇을 묻는가 | 어디가 답하는가 |
| --- | --- |
| 이번 변경이 제품을 나아지게 했는가 | `scripts/eval.sh` 의 계층 점수 |
| 이 저장소는 L0~L5 중 어디인가, 없는 요소는 무엇인가 | [../../SKILL.md](../../SKILL.md) 의 하네스 감사 모드 |
| **각 요소가 얼마나 튼튼한가, 다음에 무엇을 보완하는가** | **이 스킬** |
| 낡거나 겹치는 것을 무엇을 덜어낼까 | [../harness-gardener/SKILL.md](../harness-gardener/SKILL.md) |

감사 모드를 먼저 수행해 L0~L5 를 확정한 뒤 이 스킬로 내려옵니다. 순서를 바꾸면 성숙도가 낮아 아직 존재하지도 않는 요소를 채점하게 됩니다.

## 채점 기준

기준은 [rubric.md](rubric.md) 가 소유합니다. 여섯 축과 등급 문구, 산출 형식이 거기 있습니다. **이 문서에 기준을 복제하지 마십시오.** 축을 늘리거나 등급 문구를 바꾸는 것은 평가 정의 변경이므로 [../../rules/evaluation-integrity.rule.md](../../rules/evaluation-integrity.rule.md) EI-2 에 따라 사람이 결정합니다.

## 절차

### 1. 채점자를 분리합니다

**하네스를 만든 주체가 그 하네스를 채점하지 않습니다.** 구현자가 자기 결과를 평가하면 확인 편향과 기준 완화가 그대로 들어옵니다. 근거는 [../../references/generator-evaluator.md](../../references/generator-evaluator.md) 입니다.

요소 15개를 세 그룹으로 나눠 서로 독립된 채점자에게 맡깁니다. 그룹을 나누는 이유는 병렬 실행이 아니라 **깊이**입니다. 한 채점자가 15개를 모두 보면 실행 확인을 생략하고 파일을 읽는 것으로 대체하게 됩니다.

| 그룹 | 요소 |
| --- | --- |
| 1 | HE-1 AGENTS.md, HE-2 CLAUDE.md, HE-3 documentation, HE-4 architecture rules, HE-5 tests |
| 2 | HE-6 lint rules, HE-7 static analysis, HE-8 skills, HE-9 subagents, HE-10 hooks |
| 3 | HE-11 scripts, HE-12 tools, HE-13 memory, HE-14 evaluation, HE-15 workflow |

각 채점자에게 다음을 지시합니다. [rubric.md](rubric.md) 를 먼저 완전히 읽을 것. 요소 정의는 [../../references/harness-elements.md](../../references/harness-elements.md) 3절이 정본임. 저장소를 수정하지 말 것. 실험이 필요하면 사본에서 할 것.

### 2. 실행해서 채점하게 합니다

파일이 존재한다는 사실은 근거가 아닙니다. 채점자는 명령을 실제로 돌리고 그 출력을 근거로 씁니다.

```bash
harness/scripts/verify.sh --list
harness/scripts/self-check.sh
harness/hooks/guard-evaluation-tampering.sh --list
harness/scripts/improvement-log.sh list
cat .harness/verify.json .harness/latest-eval.json
```

`R`(회귀 방어) 축에서 4점을 주려면 **그 요소를 실제로 깨뜨렸을 때 검사가 실패하는 것을 확인**해야 합니다. 대상 저장소가 아니라 사본에서 깨뜨립니다.

`D`(문서 부패) 축은 읽어서 그럴듯하면 주는 점수가 아닙니다. 문서에 적힌 값과 실제 값을 **쌍으로 대조**합니다. 표에 나열된 항목과 코드의 배열, 문서가 말하는 명령과 실제로 생성되는 명령, 문서가 가리키는 경로와 실재 여부입니다.

### 3. 후하게 주지 못하게 합니다

채점자에게 다음을 명시합니다. 3점 이상은 실행 출력이나 파일의 특정 줄을 인용할 수 있을 때만 줍니다. 분포를 고르게 만들지 않습니다. 확인할 수 없으면 점수 대신 `미확인` 을 쓰고 이유를 적습니다. 미확인을 0점이나 만점으로 바꾸지 않습니다.

### 4. 결과를 대조합니다

세 채점 결과가 도착하면 합치기 전에 다음을 확인합니다.

- 같은 근거에 서로 다른 점수가 매겨진 축이 있는가. 있으면 근거가 강한 쪽을 택하고 판단 근거를 남깁니다.
- `미확인` 이 몇 건인가. 미확인이 많으면 그것 자체가 관측 결손이며 보고서에 그대로 남깁니다.
- 만점이 몰려 있는 축이 있는가. 있으면 그 축이 변별하지 못하는 것이므로 축의 결함으로 기록합니다.

점수를 평균 내거나 반올림해 하나로 합치지 마십시오. 축별 점수를 그대로 보존합니다.

### 5. 보완 우선순위를 만듭니다

총점이 낮은 순이 아니라 **영향 대비 비용** 순으로 정렬합니다. 각 항목에 다음을 답니다.

- 어느 요소의 어느 축인가
- 지금 점수와 보완 후 예상 점수
- 보완 비용(낮음·중간·높음)
- 이미 있는 improvement log 후보와 연결되는가

`E`(강제력) 축이 낮은 항목을 우선합니다. 번들의 HP-2 가 자연어 지시를 검증으로 승격시키라고 규정하므로, 강제력을 한 단계 올리는 것이 같은 비용의 다른 개선보다 값이 큽니다.

### 6. 보고서를 냅니다

기본 산출은 HTML 보고서 한 장입니다. 담아야 할 것은 다음과 같습니다.

1. 여섯 축의 정의와 등급 (읽는 사람이 점수를 해석할 수 있어야 합니다)
2. 15개 요소 × 6축 점수표. 축별 값이 한눈에 비교되어야 합니다
3. 축별 총계. 어느 축이 저장소 전체에서 약한지 드러나야 합니다
4. 보완 우선순위 목록
5. `미확인` 항목과 그 이유
6. 채점에 실제로 사용한 명령

점수를 통과·실패로 바꾸지 마십시오. 이 채점은 게이트가 아니라 진단입니다. 임계값을 만들어 합격 여부를 판정하기 시작하면 그 순간부터 점수를 올리는 가장 값싼 경로가 선택됩니다([../../rules/evaluation-integrity.rule.md](../../rules/evaluation-integrity.rule.md) EI-3).

## 완료 조건

- 요소 15개 전부에 여섯 축 점수 또는 명시적 `미확인` 이 있습니다.
- 3점 이상인 모든 점수에 실행 출력 또는 `파일:줄` 근거가 붙어 있습니다.
- `R` 4점인 항목은 깨뜨렸을 때 실패하는 것을 실제로 확인했습니다.
- `D` 점수마다 대조한 문서와 실제 값이 함께 적혀 있습니다.
- 채점자가 하네스를 만든 주체와 분리되어 있습니다.
- 보완 우선순위가 총점이 아니라 영향 대비 비용으로 정렬되어 있습니다.
- 대상 저장소를 수정하지 않았습니다.

## 하지 않는 것

- 자기가 만든 하네스를 자기가 채점하지 않습니다.
- 점수에 임계값을 붙여 합격·불합격을 판정하지 않습니다. 진단이지 게이트가 아닙니다.
- 축을 추가하거나 등급 문구를 바꾸지 않습니다. 평가 정의 변경은 사람이 합니다.
- 분포를 고르게 만들려고 점수를 조정하지 않습니다.
- `미확인` 을 0점이나 만점으로 바꾸지 않습니다.
- 채점 중에 발견한 결손을 그 자리에서 고치지 않습니다. 이 스킬은 읽기 전용이며, 고치는 것은 improvement log 후보를 거쳐 harness-promote 가 판정합니다.
- 이전 라운드의 점수를 근거 없이 다시 씁니다. 매 라운드 실행 근거를 새로 만듭니다.
