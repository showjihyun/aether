# 하네스 구성요소 채점 기준 (HE-RUBRIC/1)

이 문서는 [SKILL.md](SKILL.md) 의 채점 기준 정본입니다. 하네스 번들의 15개 구성요소(`HE-1`~`HE-15`)를 여섯 축으로 채점합니다. 축과 등급은 번들 자신의 규범에서 끌어왔습니다. 임의로 축을 추가하거나 등급 문구를 바꾸지 마십시오. 그것은 평가 정의 변경이며 [../../rules/evaluation-integrity.rule.md](../../rules/evaluation-integrity.rule.md) EI-2 에 따라 사람이 결정합니다.

| 소유자 | 재검토 조건 |
| --- | --- |
| unassigned | 축이 변별하지 못하는 것이 두 라운드 연속 관측될 때, 또는 `HE-*` 인벤토리가 바뀔 때 |

## 채점 원칙

1. **파일이 존재한다는 사실은 근거가 아닙니다.** [../../SKILL.md](../../SKILL.md) 의 공통 근거 모델이 그렇게 규정합니다. 실행한 명령과 그 출력만 근거입니다.
2. **후하게 주지 마십시오.** 3점 이상은 실행 결과나 파일의 특정 줄을 인용할 수 있을 때만 줍니다. 근거를 대지 못하면 2점 이하입니다.
3. **분포를 고르게 만들지 마십시오.** 실제로 약한 요소는 낮게 나와야 합니다. 평균을 맞추려고 조정하지 마십시오.
4. **모르면 모른다고 하십시오.** 확인할 수 없으면 점수 대신 `미확인` 을 쓰고 이유를 적습니다. 미확인을 0점이나 만점으로 바꾸지 마십시오.
5. 각 점수마다 **근거 한 줄**을 답니다. `파일:줄` 또는 실행한 명령과 출력 요약입니다.

## 여섯 축 (각 0~4점, 합 24점)

### P — 존재 (Presence)

| 점수 | 기준 |
| --- | --- |
| 0 | 산출물이 없습니다 |
| 1 | 계획·언급만 있고 파일이 없습니다 |
| 2 | 템플릿이나 자리표시자 상태입니다 |
| 3 | 실체화되어 내용이 채워져 있습니다 |
| 4 | 실체화되었고 **이 저장소에 실제로 적용**되어 있습니다 |

### E — 강제력 (Enforcement)

[../../references/harness-elements.md](../../references/harness-elements.md) 2절의 `EL-*` 사다리를 그대로 씁니다. "이 요소를 다음 에이전트가 놓쳤을 때 실패로 드러나는가"로 판정합니다.

| 점수 | 기준 |
| --- | --- |
| 0 | 놓쳐도 아무 일도 일어나지 않습니다 (EL-1 instruction) |
| 1 | 근거는 제공하지만 강제하지 않습니다 (EL-2 doc) |
| 2 | 호출하거나 실행할 때만 드러납니다 (EL-3 skill·subagent, EL-4 script) |
| 3 | 검증 단계에 포함되어 실행하면 반드시 드러납니다 (EL-5 test) |
| 4 | 코드 형태로 판정되거나 에이전트가 실행 여부를 고를 수 없습니다 (EL-6 lint·arch-rule, EL-7 hook) |

### X — 실행 증거 (Executed evidence)

| 점수 | 기준 |
| --- | --- |
| 0 | 한 번도 실행된 적이 없습니다 |
| 1 | 사람이 수동으로 1회 실행했습니다 |
| 2 | 수동 반복 실행이 가능하나 자동 호출되지 않습니다 |
| 3 | `harness.config` 의 verify 단계로 등록되어 있습니다 |
| 4 | 매 실행마다 자동으로 돌고 `.harness/` 에 근거가 남습니다 |

### G — 소유와 수명 (Governance)

[../../rules/harness-gc.rule.md](../../rules/harness-gc.rule.md) GC-2 를 씁니다.

| 점수 | 기준 |
| --- | --- |
| 0 | 소유자도 재검토 조건도 없습니다 |
| 1 | 둘 중 하나만 있습니다 |
| 2 | 둘 다 있으나 형식적입니다 (`unassigned`, 근거 없는 날짜) |
| 3 | 둘 다 있고 재검토 조건이 검증 가능한 형태입니다 |
| 4 | 위에 더해 청소 라운드가 실제로 이 요소를 재검토한 기록이 있습니다 |

### R — 회귀 방어 (Regression coverage)

| 점수 | 기준 |
| --- | --- |
| 0 | 이 요소가 깨져도 어디에도 드러나지 않습니다 |
| 1 | 사람 리뷰에서만 드러납니다 |
| 2 | 수동으로 재현할 수 있습니다 |
| 3 | 자동 검사가 있어 깨지면 실패합니다 |
| 4 | 자동 검사가 있고, **깨뜨렸을 때 실제로 실패하는 것을 확인**했습니다 |

### D — 문서 부패 (Documentation decay)

이 축은 요소 자체의 건강이 아니라 **그 요소를 설명하는 문서가 현재 상태를 맞게 말하는가**를 봅니다. 한때 맞았지만 지금은 틀린 문서가 대상입니다. 점수가 높을수록 건강합니다.

부패의 형태는 다섯 가지입니다. 문서가 현재 동작을 틀리게 설명함. 없는 대상을 가리킴. 같은 사실이 두 곳에 있고 한쪽만 갱신됨. 근거가 사라진 규칙이 남아 있음. 자리표시자나 예시가 실제 값인 것처럼 남아 있음.

| 점수 | 기준 |
| --- | --- |
| 0 | 부패가 확인되었습니다. 문서가 현재 동작을 틀리게 설명하거나, 없는 대상을 가리키거나, 만료된 근거가 남아 있습니다 |
| 1 | 중복된 사실이 서로 어긋납니다. 한쪽만 갱신된 흔적이 있습니다 |
| 2 | 부패는 확인되지 않았으나 같은 사실이 여러 곳에 복제되어 있어 어긋날 여지가 큽니다 |
| 3 | 정본이 하나이고 나머지 자리에는 링크만 있습니다. 부패가 확인되지 않았습니다 |
| 4 | 위에 더해 문서와 구현의 일치를 **기계가 검사합니다** |

D 를 채점할 때는 문서에 적힌 값과 실제 값을 직접 대조하십시오. 표에 나열된 항목과 코드의 배열, 문서가 말하는 명령과 실제로 생성되는 명령, 문서가 가리키는 경로와 실재 여부를 각각 확인합니다. 읽고 그럴듯하면 3점을 주는 방식으로 채점하지 마십시오.

D 가 낮은 것과 R 이 낮은 것은 다른 문제입니다. R 은 요소 자체가 깨졌을 때 드러나는가를 묻고, D 는 요소를 설명하는 문서가 지금도 맞는 말을 하는가를 묻습니다. 구현이 멀쩡한데 문서만 낡은 경우가 D 의 대상입니다.

## 산출 형식

요소마다 정확히 다음 블록을 냅니다. 다른 형식을 쓰지 마십시오.

```text
### HE-N <요소 이름>
P: <0-4> | <근거 한 줄>
E: <0-4> | <근거 한 줄>
X: <0-4> | <근거 한 줄>
G: <0-4> | <근거 한 줄>
R: <0-4> | <근거 한 줄>
D: <0-4> | <근거 한 줄. 대조한 문서와 실제 값을 함께 적습니다>
합계: <0-24>
가장 큰 결손: <한 문장. 이 요소에서 무엇을 보완하면 점수가 가장 많이 오르는가>
보완 비용: 낮음 | 중간 | 높음
```

마지막에 다음을 덧붙입니다.

```text
## 이 그룹의 총평
- 가장 약한 요소 1개와 그 이유
- 점수는 높지만 실제로는 취약한 요소가 있다면 1개와 그 이유
- 확인하지 못한 것
```

## 이 기준이 하지 않는 것

- 합격선을 두지 않습니다. 이 채점은 진단이지 게이트가 아닙니다. 임계값을 붙이는 순간 점수를 올리는 가장 값싼 경로가 선택됩니다.
- 요소 간 점수를 더해 저장소 하나의 값으로 만들지 않습니다. 축별·요소별로 보아야 다음에 무엇을 고칠지 나옵니다.
- 성숙도(L0~L5)를 대체하지 않습니다. 성숙도를 먼저 확정한 뒤 이 기준으로 내려옵니다.
