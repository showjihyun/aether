## 2. 설계

### 2.1 캔버스는 npm 의존 하나로 그립니다 (D-1 — OQ1 의 답)

**`@xyflow/react`**(React Flow 의 현재 패키지 이름)를 `apps/web` 의 dependency 로 **정확한 버전에 핀**해 들입니다. 빌드가 번들에 넣으므로 런타임 네트워크가 없고(R-9), CDN 은 쓰지 않습니다.

직접 SVG 로 그리는 쪽을 택하지 않은 이유는 하나입니다 — 캔버스의 값은 그리는 것이 아니라 **끌기·연결·확대·선택**이고, 그것을 직접 만들면 이 Phase 가 상호작용 구현으로 덮입니다. 대가는 의존 하나와 번들 크기이고, 그 대가는 **DESIGN.md 1절에 행으로 적히기 전에는 지불하지 않습니다**(R-10). 즉 **DESIGN.md 수정이 캔버스 단위보다 앞**입니다.

색·간격·타이포는 그 라이브러리의 기본 테마를 쓰지 않고 **DESIGN.md 의 토큰**으로 덮습니다. 캔버스가 임의 색을 쓰는 첫 자리가 되지 않습니다.

### 2.2 쓰기는 서버 액션이 받습니다 (D-2 — OQ2 의 답, 🔒 사람)

중계(`apps/web/lib/relay.ts`)의 `ALLOWED_ROUTES` 를 **늘리지 않습니다.** 브라우저는 same-origin 서버 액션으로 입력만 보내고, web 서버가 SDK 로 api 를 부릅니다. MVP-2e 의 D-18 이 대화의 실행 시작에 대해 한 선택과 **같은 선택**이고, 같은 이유입니다 — 중계는 키를 들고 있어 **열어 둔 만큼이 그대로 공개**되고, 쓰기를 통과시키는 구멍을 만드는 대신 요청 모양을 web 이 소유합니다.

이 선택이 **지우지 않는 비용**을 그대로 적습니다: 사용자 세션이 없으므로 **web 에 닿는 사람은 Agent·Workflow 를 만들 수 있습니다.** 읽기에 대해 D-15 가 같은 말을 했고, 이 Phase 가 그것을 **쓰기로 넓힙니다.** 그 선을 사람 단위로 긋는 것은 Phase 8 Trust Layer 입니다(C-5).

### 2.3 노드 실행은 투영으로 옵니다 (D-3 — OQ3 의 답)

노드 실행은 `data.workflow_run_executions` 에 있고 api 역할은 `data` 에 **USAGE 조차 없습니다**(마이그레이션 0001 의 GRANT — spec 0001 R-7). 권한을 넓히지 않고, 이 저장소에 **이미 세 번 쓰인 모양**을 네 번째로 씁니다.

| 선례 | worker → api 통지 | api 가 적용하는 곳 |
| --- | --- | --- |
| Agent Run 상태 | `aether:runs:status` | `control.runs` |
| Knowledge 적재 상태 | `aether:knowledge:ingestions:status` | `control.knowledge_ingestions` |
| Workflow Run 상태 | `aether:workflow_runs:status` | `control.workflow_runs` |
| **이번** | **노드 실행 통지**(새 스트림 또는 위 Workflow 스트림의 확장 — plan 이 고릅니다) | **`control.workflow_node_executions`**(새 투영 테이블) |

- **쓰는 주체는 api 입니다.** worker 는 통지만 보냅니다(`aether_data` 역할은 `control` 에 쓸 수 없습니다 — 이 사실이 설계를 결정합니다). AR-13 의 평면 경계가 그대로입니다. **spec 0005 개정 2 가 같은 이유로 같은 선택을 했습니다** — 그 개정의 요점은 "GRANT 를 넓히지 않은 것" 이고, 이 spec 도 같습니다.
- **투영은 사본이고 정본이 아닙니다.** `data.workflow_run_executions` 가 정본이고, 투영에는 **화면이 쓰는 열만** 둡니다 — 노드 id·종류·상태·시각·실패 이유. **노드 출력(`output`)은 투영에 넣지 않습니다**(2.4 와 C-3).
- 조회는 `GET /workflow-runs/{id}/nodes` 이고 페이지 규칙은 `GET /agents` 를 베낍니다(spec 0006 D-3 과 같은 선).

### 2.4 노드 출력은 화면에 가지 않습니다 (D-4)

spec 0005 **D-8**(노드 출력을 `data` 에 둔다)의 되돌리기 조건은 [../intents/intent.md](../intents/intent.md) 가 적어 둔 그대로입니다 — **"소비자가 둘로 늘어나는 변경이 오면 그 PR 이 이 결정을 다시 엽니다."** 이 spec 은 그 문을 **열지 않습니다**: 투영이 상태와 시각만 들고 가므로 출력의 소비자는 여전히 `CONDITION` 판정 **한 곳**이고, `tests/arch/test_workflow_output_stays_in_data.py` 가 그대로 통과합니다.

노드의 출력을 화면에서 보는 일은 **Workflow 디버거**의 몫이고 intent 가 그것을 이번 범위 밖에 두었습니다. 보고 싶어지는 순간이 오면 그때 D-8 을 다시 엽니다.

### 2.5 설정 패널은 넷이고 Policy 는 읽기만입니다 (D-5 — OQ6 의 답, 🔒 사람)

원본 11장의 다섯 중 **Model·Tools·Context·Memory** 넷을 편집 대상으로 두고, **Policy 는 보여만 줍니다**(지금 무엇이 허용되어 있는가). 바꾸는 길은 `aether-api permissions allow` 가 그대로 소유합니다.

이유는 범위가 아니라 경계입니다 — Policy 는 **기본 deny** 이고 그것을 화면에서 넓히는 것은 세션도 역할도 없는 화면에 **권한 부여 능력**을 주는 일입니다. Policy 편집 화면은 Phase 9 자리입니다. 읽기만 두는 것이 **자리표시가 아닌 이유**는 그 화면이 실제 허용 목록을 보여주기 때문입니다(DESIGN 9절).

### 2.6 자연어 Agent 생성은 이번이 아닙니다 (D-6 — OQ4 의 답)

원본 11장의 `"Create a customer support agent."` 는 **Phase 6 이후**로 보냅니다. 모델 호출이고 프롬프트 설계이며 판정이 비결정적이라, 이번 Phase 의 판정 가능한 요구(R-1 ~ R-12)와 성질이 다릅니다. 같은 Phase 에 넣으면 "화면에서 Agent 를 만들 수 있다" 의 판정이 모델 품질에 걸립니다.

**하지 않는 것이 아니라 미루는 것**이고, 미룬 자리는 intent 의 Non-goals 와 이 문서 6절에 남습니다.

### 2.7 a11y 는 단계로 넣고 첫 바퀴는 막지 않습니다 (D-7 — OQ5 의 답, 🔒 보호 파일·EI-2)

| 항목 | 값 |
| --- | --- |
| 도구 | **`axe-core`** — 지금 저장소의 axe 류 의존은 **0건**입니다 |
| 기준 | **WCAG 2.2 AA** |
| 대상 | 사이드바의 **여섯 경로**(`NAV_ITEMS` 다섯 + `/`) 와 이번에 생기는 Builder 화면 |
| 어디서 도는가 | **`web-unit` 과 같은 jsdom 에서 렌더한 DOM** 을 검사하는 **별 단계**. 브라우저를 띄우지 않습니다 — `e2e` 가 지금도 브라우저 없이 HTML 텍스트만 보는 것과 같은 선(spec 0006 D-20) |
| 강제 수준 | **첫 바퀴는 위반을 출력하고 단계를 실패시키지 않습니다**(`required=false`). 숫자가 보인 뒤 사람이 켭니다 |

강제 수준을 사람이 나중에 켜는 이유는 하나입니다 — **지금 위반이 몇 건인지 아무도 모릅니다.** 켜고 나서 예외 목록으로 비우는 것은 intent 의 "넘지 않을 선" 이 금지합니다. 그래서 **세는 것과 막는 것을 분리**하고, 막는 결정은 숫자를 본 사람이 합니다.

`harness.config` 변경은 **보호 파일**이고 사람이 커밋합니다. 그 PR 에 **예산 결정이 같이** 옵니다(전량 실측: CI 485,146 ms · 로컬 760,881 ms · 예산 900,000 ms).

### 2.8 저장은 새 버전이고, 화면이 그렇게 말합니다 (D-8 — OQ7 의 답)

`control.agent_versions` 는 **DB 트리거로 불변**이고(마이그레이션 0001), `PUT /agents/{id}` 는 새 버전을 만들며 충돌 시 `409 agent_version_conflict` 입니다. Workflow 정의도 버전으로 불변이고 실행 중 Run 은 핀된 버전을 씁니다.

화면은 이 사실을 **저장 버튼 자리에서** 말합니다 — "저장하면 새 버전이 만들어지고, 돌고 있는 Run 은 이전 버전을 계속 씁니다". 그리고 `409` 를 **"누군가 먼저 저장했습니다"** 로 보여줍니다. 사용자가 "고쳤는데 돌던 것이 안 바뀐다" 를 **놀라움으로 만나지 않게** 하는 것이 이 결정의 전부입니다.

### 2.9 노드 좌표는 저장하지 않습니다 (D-9)

`Node` 와 `Edge` 에는 **좌표 열이 없습니다**(`packages/workflow/.../domain/node.py` — id·kind·종류별 필드, 간선은 source·target·label). 캔버스는 열 때마다 **자동 배치**하고, 노드를 끌어 둔 자리는 저장하지 않습니다.

좌표를 정의에 넣는 쪽을 택하지 않은 이유: 정의는 **버전으로 불변**이므로 노드를 **보기 좋게 옮기는 일이 새 Workflow Version 을 만듭니다.** 그 비용은 기능 하나의 값보다 큽니다. 별도 저장소(레이아웃 테이블)를 두는 쪽은 **이번 범위 밖**입니다 — 필요가 관측되면 그때 단위로 만듭니다. 그 사이의 비용은 "열 때마다 배치가 다를 수 있다" 이고, 화면이 그 사실을 적습니다(R-12).

### 2.10 검증 단계

새 단계는 **a11y 하나**입니다(2.7). 나머지는 기존 단계가 받습니다 — `web-unit`·`web-typecheck`·`web-lint`·`web-build`·`api-integration`·`api-arch`·`e2e`. `e2e` 에 R-8 의 "만드는 경로" 한 줄이 늘어나고, 그것이 **쓰기 경로를 실제 스택에서 판정하는 유일한 자리**입니다(C-1).

### 2.11 설정 (추가되는 환경변수)

**없습니다.** 쓰기 경로가 서버 액션이므로 web 은 이미 가진 `AETHER_WEB_API_KEY`·`AETHER_API_URL` 외에 아무것도 더 요구하지 않습니다. 새 비밀값이 생기지 않는 것이 D-2 의 부수 효과입니다.

## 6. 이 spec 이 답하지 않는 것

intent 의 Non-goals 를 그대로 두고, 설계하면서 새로 뺀 것을 더합니다.

새로 뺀 것:

- **노드 좌표의 저장**(D-9). 레이아웃 테이블도, 정의 안의 좌표도 두지 않습니다.
- **노드 출력의 화면 표시**(D-4). 그것은 Workflow 디버거이고 spec 0005 D-8 을 다시 여는 일입니다.
- **`violations[]` 에 간선 식별자 추가**(D-11). api 응답을 넓히는 일이고, 필요가 관측되면 단위가 됩니다.
- **a11y 위반을 막는 임계값**(D-7). 세는 것까지가 이 spec 이고 막는 것은 사람입니다.
- **투영의 과거 데이터 채우기(backfill)**. 투영이 생긴 뒤의 Run 만 노드가 보입니다 — 그 이전 Run 의 노드는 `data` 에만 있고 화면에 오지 않습니다. 필요하면 별 단위입니다.

intent 에서 이미 뺀 것(반복하지 않고 링크): 협업 편집, Workflow 디버거, 모바일 캔버스, 화면에서의 키 발급·회전 — [../intents/0007-phase-5-visual-agent-builder.md](../intents/0007-phase-5-visual-agent-builder.md) Non-goals.
