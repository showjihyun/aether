**선행 조건은 닫혔습니다 — 다만 닫힌 방식을 그대로 적습니다.** intent [0006](0006-mvp-integration.md) 은 **2026-10-20 에 완료**됐습니다(PR #180). 그 완료는 **사람이 R-12 를 참으로 판정한 것**이고, 근거 파일 [../docs/measurements/ttfsa-2026-10-20.md](../docs/measurements/ttfsa-2026-10-20.md) 의 **측정자·단계별 시각·막힌 지점·총 시간은 전부 «기록되지 않음»** 입니다. 즉 이 문서의 초안이 전제했던 "**H-4** 가 커밋되기 전에는 승인하지 않는다" 는 **그대로 성립하지 않았습니다** — 승인의 근거는 측정 기록이 아니라 **사람의 판정**입니다. 그 사실을 조용히 넘기지 않고 여기 남깁니다. **H-4 는 여전히 열려 있고**(아래 「사람 손」), 실제 측정이 생기면 새 날짜 파일로 들어옵니다 — 그 기록은 2026-10-20 의 Quickstart 마찰 수정(F-1 ~ F-9, PR #182) **뒤의 문서**로 쟀다는 사실을 함께 적어야 합니다(EI-3).

## Problem

Phase 4 와 MVP 통합이 끝나 제품은 Agent·Workflow 를 만들고 실행하며, 화면 여섯 경로가 오프라인 스택에서 실제 데이터를 보입니다(MVP-4 의 `e2e` 가 그것을 판정합니다). **그런데 화면으로 만들 수 있는 것이 아직 하나도 없습니다.** 2026-10-20 에 관측한 사실입니다.

- **`apps/web` 의 쓰기 경로가 하나입니다.** `"use server"` 파일은 `app/agents/[id]/chat/actions.ts` 뿐이고, 폼은 `app/agents/[id]/chat/Chat.tsx` 의 입력 하나입니다(MVP-2e, D-18). 그 하나가 하는 일은 **Run 을 시작하는 것**이고, Agent 생성·수정은 없습니다.
- **중계는 `GET` 넷뿐입니다.** `apps/web/lib/relay.ts` 의 `ALLOWED_ROUTES` 는 `agents`·`runs`·`runs/:id`·`runs/:id/events` 이고 테스트가 그 개수를 네 개로 고정합니다(`route.test.ts`). Builder 는 본질적으로 **쓰기**이고, 지금 브라우저에서 api 로 쓰기가 가는 길은 그 서버 액션 하나뿐입니다.
- **Workflow 는 API 로만 조립됩니다.** `POST /workflows` 가 그래프를 받고 잘못된 그래프를 400 `invalid_workflow_graph` + `violations[]` 로 거절하지만, **그 위반을 사람이 보고 고치는 자리가 없습니다.** 지금은 거절 이유가 HTTP 응답 본문에만 있습니다.
- **노드 단위가 화면에 없고, 그것이 구조 때문입니다.** `apps/web/app/workflows/page.tsx` 는 "노드 실행 목록은 없습니다 — 그 API 가 없습니다(spec 0006 D-4)" 를 주석으로 적고 자리표시도 두지 않습니다. api 역할은 `data` 평면에 권한이 없고(spec 0001 **R-7**) 노드 실행은 `data` 에 있습니다 — **투영이 필요하고**, spec 0005 개정 4 가 그 투영을 "화면이 필요해지는 Phase 5" 로 보냈습니다. 지금 노드 출력을 읽는 곳은 실행기의 `CONDITION` 판정 **한 곳**입니다([intent.md](intent.md) H-2 의 실측).
- **자연어로 Agent 를 만드는 경로가 없습니다.** 원본 11장이 적은 `"Create a customer support agent."` 가 그것입니다. 지금 Agent 정의는 사람이 JSON 을 채워 `POST /agents` 로 보내거나 CLI 가 같은 일을 합니다.
- **프런트엔드 팩이 반쪽입니다.** `harness.config` 에 `e2e` 는 있지만(MVP-3 의 H-2b 가 더했습니다) **a11y 판정이 없습니다** — 저장소 전체에 axe 류 의존이 0건입니다. [../docs/roadmap.md](../docs/roadmap.md) Phase 5 행은 "프런트엔드 팩 단계(E2E, a11y) 활성화" 이고, P0-3b 는 "a11y 자동 판정(MVP-2 에서 켬)" 을 범위 밖에 적어 **MVP-2 로 미뤘는데 2a~2e 가 끝났어도 켜지지 않았습니다.** 미뤄진 사실만 남아 있습니다.
- **화면 단위 테스트는 이것을 못 봅니다.** `web-unit` 은 SDK 를 가짜로 바꿉니다(`improvement-log/2026-10-18-004`). 즉 **쓰기 경로를 만들면 그것을 실제로 판정하는 자리는 `e2e` 하나**이고, 그 단계는 지금 읽기 여섯 경로만 봅니다.

지금 상태를 한 줄로 적으면: **보는 것은 되고 만드는 것은 안 됩니다.** 원본 11장의 목표가 "개발자뿐 아니라 일반 사용자도 Agent 를 만들 수 있도록" 인데, 일반 사용자가 쓸 수 있는 생성 경로가 0건입니다.

## Proposed Outcome

끝났을 때 **관측되어야 하는 것**만 적습니다. 어떻게 만들지는 spec·plan 의 일입니다.

1. **화면에서 Agent 를 만들어 돌릴 수 있습니다.** 생성·수정이 화면에서 되고, 수정은 **새 Agent Version** 을 만듭니다(`control.agent_versions` 의 불변 트리거가 이미 그것을 강제합니다 — 화면이 그 사실과 어긋나지 않습니다).
2. **Workflow 그래프를 화면에서 조립하고, 거절 이유가 그 자리에 보입니다.** `violations[]` 가 노드·엣지 위의 문장으로 옵니다. 잘못된 그래프를 저장할 수 없고, 왜 안 되는지를 응답 본문을 열지 않고 알 수 있습니다.
3. **노드 단위가 보입니다.** Workflow Run 의 노드 실행이 조회되고, 그 조회는 **api 가 `data` 를 직접 읽지 않고 투영으로** 옵니다(R-7·AR-13 를 깨지 않습니다).
4. **쓰기 경로의 인증이 한 가지로 정해져 문서에 있습니다.** 중계 허용 목록이 늘었다면 늘어난 만큼이 그 파일에서 명시적이고, 늘리지 않았다면 쓰기를 무엇이 받는지가 적혀 있습니다. **키를 들고 있는 프로세스가 공개하는 면적**이 이 결정의 값입니다.
5. **프런트엔드 팩이 켜집니다.** 화면의 a11y 판정이 `verify.sh` 의 단계로 있고, `e2e` 가 **읽기뿐 아니라 만드는 경로**를 한 번 지납니다.
6. **위 다섯이 오프라인에서 성립합니다.** 캔버스가 런타임에 네트워크를 쓰지 않습니다(DP-4).

## Constraints

- **`apps/web` 은 `packages/sdk` 외의 `packages/*` 를 import 하지 않습니다**(AR-1). 캔버스가 Workflow 의 도메인 타입을 직접 쓰고 싶어지는 자리가 여기입니다.
- **api 는 `data` 를 읽지 않습니다**(R-7). 노드 실행을 보이려면 투영이 먼저이고, 투영 없이 권한을 넓히는 쪽은 선택지가 아닙니다.
- **브라우저 인증은 D-15 의 중계뿐이고 사용자 세션은 Phase 8 입니다.** 화면에 로그인이 없으므로 "누가 만들었는가" 를 화면이 답할 수 없습니다. 쓰기 경로는 그 공백 위에 놓입니다.
- **오프라인이 제품 요구입니다**(DP-4). 캔버스 라이브러리를 CDN 에서 받는 구성은 성립하지 않고, 폰트·아이콘도 같습니다.
- **표현 규약은 [../DESIGN.md](../DESIGN.md) 입니다** — shadcn/ui 기본값과 토큰만. 캔버스가 임의 색을 쓰는 첫 자리가 될 수 있고, 그 예외를 만들지 않습니다.
- **단계 추가는 예산 결정과 함께 옵니다.** 2026-10-20 실측 전량은 CI **485,146 ms**, 로컬 **760,881 ms**(예산 900,000 ms)입니다. a11y 단계는 보호 파일 변경이고 임계값은 사람이 소유합니다(EI-2).
- 비밀값을 코드·로그·커밋에 남기지 않습니다. 쓰기 경로가 키를 다루므로 이 제약이 설계에 직접 걸립니다.

## Non-goals

**나중에 할 것**과 **아예 하지 않을 것**을 구분합니다.

나중에(해당 Phase 에서):

- Model Registry·모델 선택 UI(Phase 6), 제품 Evaluation 화면(Phase 7 — `packages/evaluation` 은 지금도 빈 껍데기입니다), Trust Layer 와 **사용자 세션·로그인**(Phase 8), Policy 편집 화면(Phase 9), 멀티테넌시·Workspace(Month 6), Marketplace(Phase 13).

이번에 하지 않을 것:

- **협업 편집**(동시 커서·충돌 병합). 사용자 모델이 없으므로 성립하지 않습니다.
- **Workflow 디버거**(노드 단위 스텝 실행·중단점). 보는 것과 조종하는 것은 다른 일입니다.
- **모바일 레이아웃의 캔버스.** 앱 셸의 반응형은 유지하되 캔버스는 `lg` 이상을 전제합니다.
- **화면에서의 키 발급·회전.** 지금처럼 `aether-api keys create` 가 소유하고 사람이 합니다.

| a11y 단계 앞 | `harness.config` 변경 — 보호 파일이고 `harness-change` 라벨이 필요합니다. **예산 결정이 같이 옵니다** |

## 넘지 않을 선

- **권한을 넓혀 투영을 건너뛰지 않습니다.** api 가 `data` 를 읽게 만드는 쪽은 선택지가 아니라 R-7 의 위반입니다.
- **쓰기 경로를 "임시로" 열지 않습니다.** 중계는 열어 둔 만큼이 그대로 공개됩니다 — 그 파일의 주석이 그 사실을 적고 있고, 한 줄 넓히는 변경도 사람이 봅니다.
- **a11y 판정을 켜고 위반을 예외 목록으로 비우지 않습니다.** 켤 수 없으면 켜지 않고, 그 사실을 적습니다.
- **화면이 거짓말하지 않습니다.** 수정이 새 버전을 만든다면 화면이 그렇게 말하고, 이력이 없으면 없다고 말합니다(MVP-2e 가 세운 선입니다).
