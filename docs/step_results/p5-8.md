# P5-8 — a11y 러너 (숫자를 먼저 봅니다)

**명령 하나가 열다섯 화면을 jsdom 에 렌더해 WCAG 2.2 AA 로 검사하고 경로별 건수를 냅니다.** 이 단위는 **러너를 만드는 단위**이고, `harness.config` 에 단계로 등록하는 것과 강제 수준은 사람의 것입니다(H-2·H-3). 그래서 **위반이 있어도 실패로 끝내지 않습니다** — 숫자를 보기 전에 게이트를 조이지 않습니다(spec 0007 D-7).

## 무엇이 생겼는가

- **러너 하나** — `pnpm -F @aether/web run test:a11y`. `apps/web/a11y/run.a11y.tsx` 가 본체이고 `apps/web/vitest.a11y.config.ts` 가 `*.a11y.tsx` 만 집습니다(기존 `test:unit` 의 단언은 건드리지 않았습니다).
- **대상 수집** — `apps/web/a11y/targets.ts` 의 `scanRoutes` 가 `app/**/page.tsx` 를 **파일 시스템에서** 모읍니다(`app/api` 는 라우트 핸들러라 제외). 경로를 손으로 적지 않습니다 — `app/nav-routes.test.ts` 와 같은 결입니다.
- **입력 표** — `apps/web/a11y/fixtures.ts`. 경로를 키로 `params`·`searchParams`·SDK 가짜 응답을 둡니다.
- **의존 하나** — `axe-core`(devDependency). 브라우저는 띄우지 않습니다.
- **문서** — `DESIGN.md` 10절의 접근성 행을 실제와 맞췄습니다.

**숫자 (2026-10-24 실측)** — 열다섯 경로 전부 **위반 규칙 0건·요소 0건**입니다. 그리고 **그 0 의 범위**:

| 판정불가(incomplete) 규칙 | 건수 | 어디 |
| --- | --- | --- |
| `color-contrast` | 15 | **열다섯 경로 전부** |
| `aria-prohibited-attr` | 3 | `/agents/[id]/chat`, `/workflows/[id]`, `/workflows/new` |
| `label-content-name-mismatch` | 1 | `/agents` |

통과 규칙 수는 경로별 12~20. **소요**(의존 설치된 로컬) `test:a11y` 벽시계 **3.8~4.6초**(재실측 3회 4.4·4.45·4.56초, vitest Duration 3.82s).

## 왜 그렇게 했는가

- **이 단위의 유일한 거짓 성공은 「아무것도 검사하지 않은 초록」입니다.** 그래서 판정의 무게가 위반 건수가 아니라 **대상이 실재하는가**에 실려 있습니다. 대상 0개면 실패하고, 스캔된 경로가 입력 표에 없으면 실패하며, `<main>` 이 비었거나 axe 가 아무 규칙도 돌리지 않았으면 실패합니다. 위반은 **실패가 아닙니다**(D-7, 첫 바퀴).
- **표에 없는 SDK 메서드 호출을 경로별로 실패시킵니다.** 페이지들은 SDK 호출을 `try/catch` 로 감싸므로 가짜 client 가 거절하면 **오류 화면이 렌더되고도 초록**이 됩니다 — 의도한 화면이 아닌 것을 검사하는 조용한 퇴화입니다. Proxy 가 미등록 메서드 접근을 기록하고 경로마다 **0건을 단언**합니다.
- **0 건이 공허하지 않다는 증거를 러너 안에 둡니다.** `alt` 없는 `<img>` 가 `image-alt` 위반으로 **잡히는지** 확인합니다 — 탐지기가 죽은 0 과 깨끗한 0 을 구별하는 자리입니다.
- **판정불가 규칙 id 를 출력합니다.** 이 숫자가 사람의 예산·강제 수준 결정으로 올라가므로 "0건" 만으로는 부족합니다. `color-contrast` 가 15경로 전부 판정불가라는 것이 숫자로 남아야 `required=true` 가 무엇을 지키는 약속인지 알 수 있습니다.
- **셸 안에서 렌더합니다** — `ThemeProvider` → `TooltipProvider` → `AppShell` + `Toaster`. 랜드마크·내비게이션이 검사 범위에 들어옵니다. `layout.tsx` 의 `<html>`/`<body>` 는 jsdom 루트에 올릴 수 없어 렌더하지 않습니다.
- **제품 마크업을 고치지 않았습니다.** 러너를 만드는 단위이고 숫자를 먼저 봅니다 — 그리고 고칠 위반이 0건이었습니다.

## 하네스 근거

- **red 증거 ①**(대상 수집이 빔) — 러너의 수집을 `slice(0, 0)` 으로 비운 상태에서 `test:a11y` 가 exit 1: `× 검사 대상이 있고 모두 표에 항목이 있다 (0개면 실패)` → `AssertionError: expected [Function] to not throw … 'Error: a11y 검사 대상이 0개입니다'`. 되돌린 뒤 exit 0.
- **돌연변이 증거** — 그 가드를 `if (false && routes.length === 0)` 로 무력화하고 수집도 비우면 `Tests 2 passed`, **exit 0** — 아무것도 검사하지 않고 초록이 됩니다. 이 거짓 성공 경로를 가드가 막습니다. 두 변경 모두 되돌리고 잔존 0건을 확인했습니다.
- **red 증거 ②**(리뷰 반려로 추가) — `/workflows/[id]` 의 `getWorkflow` 를 입력 표에서 빼면, 고치기 **전**에는 `17 passed` exit 0 이었고(오류 화면을 검사하고도 초록), 고친 **뒤**에는 `AssertionError: /workflows/[id]: 표에 없는 client 메서드 호출: getWorkflow` 로 exit 1. 되돌린 뒤 `17 passed`.
- `apps/web/a11y/targets.test.ts` — 수집과 표 대조의 단위 테스트 4건. `test:unit` 이 집습니다.
- **규칙을 약화한 곳이 0건입니다** — `rules: {…enabled:false}`·`disableOtherRules`·위반 id 무시 목록 **없음**. 범위는 태그 다섯(`wcag2a`·`wcag2aa`·`wcag21a`·`wcag21aa`·`wcag22aa`)으로만 고릅니다. 태그는 검사 범위이고 예외 목록이 아닙니다.
- 로컬 전량 **17/17 pass**(아래 「정한 것과 다른 점」의 재실행 포함), 예산 900,000 ms 안.

## 정한 것과 다른 점

- **plan 의 「여섯 경로 + Builder」를 목록으로 적지 않고 스캔했습니다**(개정 5 ①). 그 표현은 화면이 늘면 낡는 목록이고, 목록이 조용히 비면 그것이 바로 이 단위가 막아야 하는 거짓 초록입니다. `app/**/page.tsx` 를 모아 **열다섯 경로**를 검사합니다 — 여섯의 상위집합이므로 좁아진 것이 없습니다.
- **리뷰에서 두 번 반려했습니다**(개정 5 ②) — 판정불가 규칙 id 가 출력되지 않아 색 대비가 판정불가인지 통과인지 알 수 없었던 것, 그리고 입력 표 누락이 실패하지 않던 것. 둘 다 고친 뒤의 숫자를 H-2 로 넘깁니다.
- **문서와 코드가 달랐습니다.** `DESIGN.md` 10절이 접근성을 "Playwright + axe … MVP-2 에서 켬" 이라고 적고 있었는데 둘 다 사실이 아닙니다 — spec 0007 D-7 이 **jsdom** 을 정했고(Playwright 는 `e2e` 의 것), 켜는 시점은 MVP-2 가 아니라 **H-2** 입니다. 조용히 한쪽을 고르지 않고 그 행을 실제에 맞췄으며, 러너가 보지 못하는 것도 같은 행에 적었습니다.
- 첫 구현이 `import.meta.glob` 으로 모듈을 모으려다 타입 오류를 냈고, 절대 경로 동적 `import` 로 바꿨습니다.

## 남긴 것

**H-2 로 넘기는 꾸러미(사람)** — `harness.config` 는 보호 파일이라 **제안만 하고 사람이 커밋**합니다. 제품 코드 변경을 같은 커밋에 섞지 않습니다(CC-5). 숫자를 고치지 않습니다(EI-2).

패치 한 줄, `HARNESS_STEPS` 의 `web-unit` 아래:

```
  "a11y|quality|false|pnpm -F @aether/web run test:a11y"
```

| 항목 | 값 |
| --- | --- |
| 현재 전량 실측 | CI 485,146 ms · 로컬 760,881 ms (plan 0007 3절이 인용한 값) |
| a11y 단계 실측 | **4,600 ms** (3.8~4.6초의 상단) |
| 더한 뒤 | CI 약 **489,700 ms** · 로컬 약 **765,500 ms** |
| 예산 `HARNESS_VERIFY_BUDGET_MS=900000` 까지 여유 | 로컬 상단에서 약 **134,500 ms (15%)** |

**예산을 올릴 필요가 없습니다** — 단계 소요가 전량의 **0.6%** 입니다. 다만 로컬 여유 15% 는 `harness.config` 주석이 이미 "임시" 라고 적은 그 15% 이고, 이 단계가 그것을 더 좁히는 것은 사실입니다.

- **H-3(강제 수준)이 알아야 할 것** — 위반 0건은 **색 대비를 보지 않은 0** 입니다. `required=true` 는 "지금의 0건을 지키겠다" 는 약속이고, 색 대비까지 지키려면 브라우저가 필요하므로 그것은 이 러너의 확장이 아니라 `e2e` 쪽 일입니다.
- **색 대비와 레이아웃 의존 규칙은 이 러너가 보지 못합니다.** jsdom 에 레이아웃과 `CanvasRenderingContext2D` 가 없습니다(`getContext not implemented` 15회).
- **문서 수준 규칙도 돌지 않습니다** — `<html lang>`·`<title>` 류. 검사 컨텍스트가 문서가 아니라 렌더 컨테이너이기 때문입니다. 제외 목록이 아니라 컨텍스트의 성질입니다.
- **브라우저에서 `fetch` 로 채우는 자식 패널**(예: `HealthzCard`, Run 이벤트 스트림)은 jsdom 에서 로딩·오류 상태로 머물 수 있습니다. 그 상태의 접근성은 검사되지만 **채워진 뒤의 화면은 이 러너의 범위가 아닙니다**.
- **`intents/mvp-backlog.md` 의 P5-8 행은 이 PR 에서 갱신하지 않았습니다** — 병합 뒤 상태 갱신에서 PR 번호와 함께 적습니다.
