# MVP-2p — web 서버가 api 를 중계

**화면이 실제 스택에서 데이터를 가져올 수 있게** 됐습니다. MVP-2a·2b 가 만든 세 화면은 **키 없이** api 를 부르고 있었고, 그래서 실제 스택에서는 전부 401 이었습니다 — 전량 verify 는 초록이었습니다.

## 무엇이 생겼는가

- **`apps/web/app/api/aether/[...path]/route.ts`** — 중계 경로. 정책은 `apps/web/lib/relay.ts` 가 소유합니다.
- **허용 목록** — `GET /agents`·`GET /runs`·`GET /runs/{id}`·`GET /runs/{id}/events` **넷뿐**입니다. 그 밖의 경로는 404, 허용 경로의 다른 메서드는 405 이고 **업스트림을 부르지 않습니다**.
- **키 주입** — 업스트림 호출에 `Authorization: Bearer ${AETHER_API_KEY}`. 브라우저가 보낸 `Authorization`·`Cookie` 는 **받지 않습니다**.
- **헤더를 걸러냅니다** — 응답은 `content-type`·`etag`·`last-modified`·`retry-after` 만 통과합니다. SSE 면 `no-cache`·`keep-alive`·`x-accel-buffering: no` 를 더합니다.
- **스트림을 그대로 흘립니다** — `upstream.body`(`ReadableStream`)를 그대로 돌려줍니다.
- **호출하는 쪽** — 서버 컴포넌트 셋은 키를 직접 넘기고, `RunTabs`(클라이언트)는 `baseUrl: "/api/aether"` 입니다. `AETHER_PUBLIC_API_URL` 은 **제거**했습니다.
- **compose·`.env.example`** — `AETHER_API_KEY: ${AETHER_WEB_API_KEY:-}` 와 발급 명령 주석.

## 왜 그렇게 했는가

- **중계는 열어 둔 만큼이 그대로 공개됩니다.** 키를 들고 있으니 제한이 없으면 web 에 닿는 사람은 누구나 그 키의 권한으로 API 전체를 — `POST`·`DELETE` 까지 — 부를 수 있습니다. 그래서 **`GET` 과 화면이 실제로 쓰는 경로만** 열었습니다. 넓히는 것은 그 자리에서 명시적으로 합니다(MVP-2c 의 대화가 `POST /agents/{id}/run` 을 더합니다).
- **서버 컴포넌트는 중계를 지나가지 않습니다.** 서버에서 서버로 가는 호출을 자기 HTTP 계층으로 되돌릴 이유가 없습니다 — 중계는 **브라우저**를 위한 것입니다.
- **응답 헤더를 통째로 베끼지 않습니다.** 베끼면 업스트림이 `Authorization` 을 에코할 때 **키가 브라우저로 샙니다**. 그 자리를 테스트가 봅니다.
- **본문을 `text()` 로 받지 않습니다.** 받으면 SSE 가 모여서 한 번에 나가고 타임라인이 "지금 무엇을 하고 있나" 를 못 보여줍니다 — 이 단위의 함정이 그것입니다.
- **키가 없으면 업스트림을 부르지 않고 503** 입니다. 401 로 흘려보내면 "키를 안 넣었다" 와 "키가 틀렸다" 가 구별되지 않습니다.
- **업스트림의 401·403 도 흘려보내지 않습니다**(리뷰에서 더했습니다). 그것은 "당신의 권한이 없다" 가 아니라 **"서버의 키가 거부됐다"** 이고, 브라우저 쪽 사람은 고칠 수 없습니다. 502 와 "키를 다시 발급해 주입하세요" 로 바꿉니다.
- **서버 경로도 같은 말을 합니다**(리뷰에서 더했습니다). 서버 컴포넌트가 키 없이 401 을 받으면 "api 가 떠 있는지 확인" 이라는 **틀린 다음 행동**이 나옵니다 — 가장 흔한 개발 실수에 대해 그렇습니다. 키가 없으면 호출하지 않고 "api 키가 없습니다" 를 그립니다.
- **오류 객체를 본문·로그에 옮기지 않습니다** — 키가 섞일 수 있는 자리입니다.

## 정한 것과 다른 점

- **허용 목록을 제가 좁혔습니다.** 사람 결정은 "web 서버가 중계" 였고, `GET` 만·경로 넷만은 **구현 쪽 판단**입니다. 좁히는 방향이므로 결정을 바꾸지 않습니다 — 넓히는 것이 결정을 바꾸는 쪽입니다.
- **업스트림 401·403 매핑과 서버 쪽 "키가 없습니다" 화면**은 리뷰에서 더했습니다(위임 범위에 없었습니다).
- **`:id` 조각은 `[A-Za-z0-9_-]+` 한 칸**입니다 — `..` 나 `a/b` 는 404 입니다. 업스트림 URL 을 만들 때도 조각마다 `encodeURIComponent` 를 씁니다.
- **`last-event-id` 는 넘깁니다** — SSE 재접속에 필요합니다(지금 화면은 "다시 연결" 이 항상 처음부터이지만, 경로를 막아 둘 이유는 없습니다).

## 남긴 것

- **🔒 사용자 세션이 없습니다.** web 에 닿는 사람은 허용 목록 범위를 **전부 읽을 수** 있습니다(모든 Run·Agent). 사람이 쿠키 세션 대신 중계를 고른 결과이고, 그 선을 더 긋는 것은 **Phase 8 Trust Layer** 자리입니다 — 반쪽짜리 권한 모델을 지금 넣으면 이전 비용만 생깁니다(spec 0005 가 승인 권한을 같은 이유로 비워 뒀습니다).
- **실제 스택에서 확인하지 않았습니다.** 키를 넣고 compose 를 띄워 브라우저로 열어 본 적이 없습니다 — 중계는 `fetch` 를 가짜로 둔 단위 테스트로만 봤고, compose 는 `config -q` 로 문법·치환만 봤습니다. **Next 서버가 실제로 청크 단위로 흘리는지는 `e2e`(MVP-4)가 처음 증명합니다** — 단위 테스트는 `relay()` 함수의 약속을 보고, Next 런타임의 버퍼링은 보지 못합니다.
- **키 발급은 사람 손입니다** — `aether-api keys create --label web`. 저는 키를 만들거나 보지 않습니다.
- **다크 모드·반응형은 보지 않았습니다**(이 단위에 화면이 없습니다).
