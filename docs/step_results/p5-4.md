# P5-4 — Agent 생성·수정 화면 (이 Phase 의 첫 쓰기 경로)

화면에서 **Agent 를 만들고 고칠 수 있습니다.** 이 단위가 만든 것은 화면 둘이지만 남긴 것은 **쓰기 경로의 모양**입니다 — P5-6(Workflow 저장)·P5-7(설정 저장)이 그 모양을 베낍니다. 그래서 판정의 절반이 "중계가 한 칸도 늘지 않았다"(spec 0007 **R-2**)입니다.

## 무엇이 생겼는가

- **화면 둘** — `app/agents/new/`(생성: 이름·시스템 프롬프트·모델 id)와 `app/agents/[id]/edit/`(수정: 이름 칸 없음). 폼은 `app/agents/AgentForm.tsx` 하나를 공유합니다.
- **서버 액션 하나** — `app/agents/actions.ts` 의 `createAgentAction`·`updateAgentAction`. 저장소의 두 번째 `"use server"` 파일이고 첫 번째(`agents/[id]/chat/actions.ts`)의 모양을 그대로 따릅니다.
- **목록에서 가는 길** — `/agents` 위의 「새 Agent」(빈 목록에서도 있습니다)와 행마다 「{이름} 편집」.
- **구조 테스트** — `tests/arch/test_use_server_actions_are_sdk_only_and_validated.py`. 19건이고 그중 **13건이 구멍 fixture** 입니다(각자 자기 위반 메시지를 주장합니다).
- 문서 — `DESIGN.md` 5절(새 화면 둘)·7절(빈 결과의 "갈 곳" 이 생겼습니다)·**7.2 쓰기 경로 규약**(신설).
- SDK·api 변경 **0건**(`createAgent`·`updateAgent`·`getAgent` 가 이미 있습니다). 새 환경변수·비밀값·npm 의존 **0건**.

## 왜 그렇게 했는가

- **쓰기를 중계에 더하지 않았습니다**(D-2, 🔒 사람). `ALLOWED_ROUTES` 는 `GET` 넷 그대로이고 `route.test.ts` 의 개수 고정 **4 가 그대로 통과**합니다 — 그것이 R-2 의 판정입니다. 중계는 키를 들고 있어 열어 둔 만큼이 그대로 공개되므로, 쓰기를 통과시키는 구멍 대신 **요청 모양을 web 이 소유**합니다.
- **인자는 원시 타입뿐이고 검증이 `createClient` 보다 앞입니다.** 객체나 `FormData` 를 통째로 받으면 브라우저가 요청 본문을 쓰는 것과 같습니다. 구조 테스트가 "인자가 처음 나오는 곳이 `typeof` 검사이고, 그 `if` 에 내용 검사가 하나 더 있고, `return` 으로 끝나며, 이 모두가 `createClient(` 앞" 을 **파일에서** 봅니다.
- **수정은 액션이 현재 정의를 읽어 보이는 칸만 교체합니다.** `PUT /agents/{id}` 는 정의를 통째로 바꾸고 폼은 두 칸만 압니다 — 브라우저가 정의를 보내면 폼에 없는 칸(tools·memory·knowledge·policy)이 **조용히 사라지고**, 브라우저가 정의 전체를 쓸 수도 있게 됩니다. 대가는 저장마다 `GET` 한 번입니다.
- **`409` 의 뜻은 부르는 쪽이 압니다** — 생성에서는 이름 충돌(`agent_name_taken`), 수정에서는 버전 충돌(`agent_version_conflict`)이라 문장이 다릅니다. 분기는 상태 코드 **필드**로 하고 문구를 파싱하지 않습니다(DESIGN 7절).
- **저장 자리가 사실을 말합니다**(R-12·spec 2.8) — "저장하면 새 버전이 만들어지고, 돌고 있는 Run 은 이전 버전을 계속 씁니다". `control.agent_versions` 가 트리거로 불변이고 돌고 있는 Run 은 핀된 버전을 쓰는 것이 그 이유입니다.
- **수정 화면은 `getAgent` 로 읽습니다.** plan 은 `getAgentVersion` 을 적었지만 `getAgent` 가 현재 정의와 `current_version` 을 함께 돌려주므로 호출 하나로 끝납니다 — 같은 값을 두 번 받는 호출을 늘리지 않았습니다.
- **세션·권한을 만들지 않았습니다.** "web 에 닿는 사람은 Agent 를 만들 수 있다" 는 spec 2.2·C-2 에서 **사람이 받아들인 비용**이고 그 선은 Phase 8 입니다. 이 단위에서 반쪽 권한 모델을 넣으면 이전 비용만 생깁니다(spec 0005 C-4 와 같은 선).

## 정한 것과 다른 점

- **`getAgentVersion` 대신 `getAgent`** — plan 2절의 P5-4 표가 적은 셋 중 하나를 쓰지 않았습니다. 위의 여섯 번째 항목이 이유입니다.
- **기존 테스트의 링크 개수 고정을 1 → 3 으로** 고쳤습니다(`app/agents/page.test.tsx`). 그 핀이 지키는 것은 "이름 칸만 링크이고 다음 쪽 링크는 `next_cursor` 가 있을 때만 생긴다" 인데, 이 단위가 링크 둘(「새 Agent」·「편집」)을 **의도적으로** 더했습니다. 핀의 뜻은 그대로 두고 숫자와 주석을 함께 고쳤습니다 — 이름 칸이 대화로 간다는 주장은 같은 테스트에 그대로 있습니다.
- 그 둘 말고는 plan 0007 2절의 P5-4 표와 같습니다.

## 남긴 것

- **`PUT /agents/{id}` 에 전제 조건(expected version)이 없습니다.** 그래서 `409 agent_version_conflict` 는 액션의 **읽기와 쓰기 사이**에 다른 저장이 끼었을 때만 납니다. 폼을 열어 둔 동안 남이 저장했다면 내 저장은 그 최신 정의 위에 **보이는 칸만** 덮어씁니다 — 남이 바꾼 `system_prompt` 는 경고 없이 내 값으로 바뀝니다. 화면은 이 사실을 주장하지 않지만(저장은 새 버전이라고만 말합니다) **"누군가 먼저 저장했습니다" 가 실제보다 드물게 뜹니다.** 엄격하게 하려면 api 가 전제 조건을 받아야 하고 그것은 이 Phase 의 범위 밖입니다 — **사람 판단 대상**으로 올립니다.
- **폼 범위는 이름·시스템 프롬프트·모델 id 셋**입니다. tools·context·memory 는 **P5-7** 의 패널 넷이고, Policy 는 그 단위에서도 **읽기만**입니다(🔒 D-5).
- **`e2e` 판정**(화면이 만든 Agent 가 목록에 보이고 한 번 고치면 버전 둘)은 **P5-9** 입니다.
- 구조 테스트의 분석기는 템플릿 리터럴의 `${}` 와 정규식 안의 따옴표를 모릅니다 — 그 한계를 모듈 docstring 에 적었습니다. 액션 파일이 그런 모양을 쓰면 테스트가 **먼저 어긋나 드러납니다**.
