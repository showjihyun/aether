# P5-6 — Workflow 캔버스 쓰기와 `violations[]` (거절이 보이는 자리)

**화면에서 Workflow 를 만들어 저장합니다.** 저장이 거절되면 **그 이유가 어긋난 노드 위에** 붙습니다. 이 단위의 어려움은 캔버스가 아니라 **쓰기 규약과 구조의 충돌**이었습니다 — `DESIGN.md` 7.2 는 서버 액션 인자를 "원시 타입만" 으로 못 박았는데 그래프는 배열 둘입니다.

## 무엇이 생겼는가

- **화면 하나** — `/workflows/new`. 노드 추가(종류 열셋)·연결·삭제·저장. `/workflows/{id}`(P5-5)는 **읽기 그대로**입니다.
- **서버 액션 하나** — `app/workflows/actions.ts` 의 `createWorkflowAction(name, graphJson)`. 저장소의 **세 번째** `"use server"` 파일이고 `app/agents/actions.ts` 의 모양을 베낍니다.
- **SDK 함수 하나** — `createWorkflow`. `updateWorkflow`(PUT)는 만들지 않았습니다.
- **문장 맵 하나** — `lib/workflowViolations.ts`. 키와 문구는 **`DESIGN.md` 6절 표가 정본**이고 화면이 문구를 새로 쓰지 않습니다.
- **R-4 순회 테스트 하나** — api 의 `Reason` 열거형 · 6절 표 · 문장 맵 **셋이 같은 키 집합**임을 판정합니다.
- **문서** — `DESIGN.md` 5절(새 화면), 6절(**위반 사유 열넷의 문장 표**), **7.3 절 신설**(그래프를 쓰는 인자).

## 왜 그렇게 했는가

- **그래프를 문자열 하나로 받습니다**(7.3). 객체·배열을 통째로 받으면 **브라우저가 요청 본문을 쓰는 것과 같아져** 7.2 가 막으려던 것이 그대로 돌아옵니다. 그래서 인자는 `name`·`graphJson` 둘이고, **모양은 액션이 소유**합니다 — 파싱한 뒤 노드·간선을 **허용 목록의 키로 다시 조립**하므로 좌표나 종류별 칸이 끼어 있어도 api 로 가지 않습니다(D-9).
- **`kind` 열셋은 컴파일이 지킵니다.** `Record<Kind, true>` 가 SDK 타입에 묶여 있어 api 에 종류가 생기거나 사라지면 빌드가 깨집니다.
- **거절을 화면의 1급 상태로 둡니다.** `400` 의 `violations[]` 는 `node_id` 가 있으면 그 카드 위에, `null` 이거나 캔버스에 없는 노드면 **그래프 수준 `role="alert"`** 에 붙습니다. **간선에는 붙이지 않습니다** — 응답에 간선 식별자가 없고(C-7), 그것 때문에 api 를 넓히지 않았습니다.
- **잘못된 그래프는 저장되지 않습니다.** 400 뒤에도 편집 상태가 남고 이동하지 않습니다(7.2).
- **종류별 설정 칸을 두지 않았습니다.** 구조만 만드는 단위이고(plan 개정 4 ②), 그래서 `AGENT` 노드를 저장하면 `agent_node_without_agent` 가 그 카드 위에 보입니다 — **거절 경로가 실제로 돌아가는 증거**이기도 합니다.
- **기존 Workflow 편집은 이 단위가 아닙니다**(개정 4 ③). plan 이 `createWorkflow` 하나만 적었고, 고치는 것은 `PUT`(새 Version)입니다.

## 하네스 근거

- `web-unit` — 캔버스 상태 → 액션이 받는 `graphJson` **정확한 문자열** 비교(좌표 키 부재 포함), 고정 400 → **어느 카드에 어느 문장**(다른 카드에는 붙지 않음), 간선 목록에는 문장 없음, 400 뒤 상태 유지, 종류 열셋의 순서, 노드 삭제 시 닿은 연결도 삭제, `localStorage` 쓰기 0건.

- 로컬 전량 **17/17 pass, 278,087 ms**(예산 900,000). `vitest` 31 파일 **353건**, sdk **51건**.

## 정한 것과 다른 점

- **`AetherHttpError` 를 한 칸 넓혔습니다** — `readonly body: unknown`. `violations[]` 를 읽을 길이 없었기 때문입니다. 본문은 **메시지에 담기지 않고**, 액션이 `detail === "invalid_workflow_graph"` 와 배열 모양을 확인한 뒤 항목만 꺼냅니다. JSON 이 아닌 본문은 `undefined` 로 두어 상태 오류가 가려지지 않습니다. 기존 생성자 호출(인자 셋)은 그대로 동작하고 그것을 테스트가 고정합니다.
- plan 의 「만드는 것」은 "노드 추가·연결·삭제" 만 적었고 **끌어서 옮기기는 두지 않았습니다** — 좌표를 저장하지 않으므로 옮긴 결과가 남지 않습니다(D-9). 남지 않는 조작을 주지 않는 쪽을 골랐습니다.

## 남긴 것

- **간선 label 입력 칸이 없습니다.** 액션은 label 을 받아 보존하지만 화면에 칸이 없습니다 — `CONDITION` 의 `true`/`false` 분기를 화면에서 만들려면 그 칸이 필요하고, 그것은 종류별 칸과 같은 단위의 몫입니다.
- **종류별 설정이 없어 지금 화면으로 만든 그래프는 `START → END` 류만 저장됩니다.** `AGENT`·`LLM`·`TOOL`·`WAIT`·`CONDITION`·`LOOP` 는 저장 시점에 거절됩니다 — 거절 문장이 그 자리에 보이는 것이 이 단위의 계약입니다.
- **`PUT` 경로는 SDK 에도 화면에도 없습니다.** 필요해지는 단위에서 잇습니다.
