# P5-7 — 설정 패널 넷 (그리고 만들지 않은 Policy 패널)

Agent 정의의 **Model · Tools · Context · Memory** 를 화면에서 고칩니다 — `/agents/{id}/settings`. 쓰기 경로의 모양은 **P5-4 가 세운 것을 그대로 베꼈습니다**(DESIGN 7.2). 이 단위에서 **만들지 않은 것**이 보고의 절반입니다: MCP Policy 읽기 전용 패널은 **읽을 API 가 없어** 만들지 않았고, 그 처리가 **H-5**(사람)입니다.

**순서를 앞당겼습니다** — Wave 5·6(캔버스)이 **H-1** 에 막혀 있고 이 단위는 그 결정과 무관합니다(plan 0007 **개정 2**).

## 무엇이 생겼는가

- **`/agents/{id}/settings`** — 패널 넷이 **한 폼**에 있고 **저장 버튼도 하나**입니다. 패널마다 저장하면 패널 수만큼 새 Version 이 생깁니다.
- **서버 액션 하나 더** — `updateAgentSettingsAction`(`app/agents/actions.ts`). `getAgent` → `updateAgent` 두 번만 부르고, 읽은 정의에서 **패널이 아는 칸만** 바꿉니다. `system_prompt` 와 정의의 `policy` 블록(타임아웃·`max_steps`·재시도·`backoff`)은 **읽은 값 그대로** 보냅니다.
- **고치는 정의 칸** — `model.id` · `tools[]` · `mcp_servers[]` · `context_budget_tokens` · `knowledge[]` · `knowledge_top_k` · `memory_enabled`. 검증은 `docs/api.md` 3절의 규칙만 따릅니다(중복 금지, 1 이상 또는 비움, `transport` 는 `stdio`/`http`).
- **`model.id` 는 한 곳에서만 고칩니다** — 수정 폼(`/agents/{id}/edit`)의 모델 칸을 **빼서** 이 패널로 모았습니다. 그 폼이 고치는 칸은 시스템 프롬프트 하나이고, `updateAgentAction` 의 시그니처가 `(agentId, systemPrompt)` 로 줄었습니다.
- **R-11 구조 테스트** — `tests/arch/test_use_server_actions_are_sdk_only_and_validated.py` 를 확장했습니다(그 파일에 분석기와 fixture 틀이 이미 있습니다). `apps/web` 전체에서 허용 목록을 **바꾸는** 경로·호출·이름이 0건임을 보고, 양성 대조 넷(경로 문자열·`allowTool`·`setToolPermissions`·`tool_permissions` 변수)과 **음성 대조 둘**(주석, 정의의 `policy` 블록)이 함께 있습니다.
- 문서 — `DESIGN.md` 5절(새 화면 행 + `/agents/{id}/edit` 행의 모델 칸 철회), `plans/0007` **개정 2**(순서와 **H-5**).

## 왜 그렇게 했는가

- **Policy 패널을 만들지 않았습니다.** spec 2.5 의 "Policy" 는 **MCP 도구 허용 목록**(`control.tool_permissions`, 기본 deny)이고 바꾸는 길은 `aether-api` CLI 가 소유합니다. 그런데 **읽는 HTTP 경로도 SDK 함수도 없습니다** — api 라우트 전체를 세어 확인했습니다. plan 의 「주의」가 그 경우를 미리 적었습니다: *"허용 목록을 읽을 API 가 없으면 만들지 않고 보고합니다 — 없는 것을 자리표시로 그리지 않습니다."* 그래서 새 api 경로·새 SDK 함수·"준비 중" 자리표시 **전부 만들지 않고** 사람 결정으로 올렸습니다(**H-5**: 읽기 경로를 단위로 열기 vs Phase 9 로 미루기).
- **저장 버튼 하나.** 패널 넷이 각자 저장하면 한 번의 설정 변경이 **새 Version 넷**을 만듭니다. `control.agent_versions` 는 불변이라 그 쓰레기는 지워지지 않습니다.
- **`model.id` 의 자리를 하나로.** 수정 폼과 설정 패널이 같은 칸을 각자의 저장 버튼으로 쓰면, P5-4 가 올린 틈(`PUT` 에 전제 조건이 없어 나중 저장이 보이는 칸을 조용히 덮습니다)이 **두 배로 넓어집니다**. D-5 가 Model 을 패널 넷의 하나로 지목했으므로 수정 폼에서 뺐습니다. **생성 화면의 모델 칸은 그대로**입니다 — 한 번에 끝나는 일이고 저장 경로가 하나입니다.
- **인자를 없애는 쪽을 골랐습니다.** `updateAgentAction` 이 모델을 인자로 받고 호출자가 현재 값을 넘기는 방식도 가능했지만, 그러면 **브라우저가 보낸 값이 모델을 덮을 수 있습니다**. 인자를 없애면 그 틈이 구조적으로 막히고, 액션이 읽은 값을 그대로 보냅니다.
- **`mcp_servers` 에 자격증명·절대 URL 칸이 없습니다.** `ref` 는 배포 설정(`AETHER_MCP_SERVERS`)이 실제 명령·URL 로 푸는 키입니다(spec 0003 2.6·2.9). 구현은 `ref` 에 `://`·`@` 가 들어오면 **거절**합니다 — api 규칙이 아니라 화면 쪽 방어이고, 그 사실을 코드가 적습니다.
- **없는 이름 경고를 발명하지 않았습니다.** `tools`·`knowledge` 의 이름은 api 가 **생성 시 검증하지 않습니다**(`docs/api.md` 3절) — 화면이 "없는 이름" 을 판정하면 api 가 하지 않는 약속을 하게 됩니다.

## 정한 것과 다른 점

- **Policy 읽기 전용 패널이 없습니다** — plan·spec 이 요구했지만 읽을 API 가 없습니다. 만들지 않고 **H-5** 로 올렸습니다(plan 개정 2).
- **수정 폼의 모델 칸을 뺐습니다** — plan 에 없던 변경이고 제 판정입니다(위의 세 번째·네 번째 항목). 깨진 P5-4 핀은 **새 사실로 고쳤습니다**: "수정 폼이 보내는 인자" 는 `(id, 프롬프트)` 가 되었고 뜻("자기가 아는 칸만 보낸다")은 그대로입니다. 테스트 하나는 지웠습니다 — "모델 id 가 `null` 이면 빈 칸" 은 **칸이 없어져** 주장할 대상이 사라졌고, 같은 파일의 "모델 칸이 없다" 와 `actions.test.ts` 의 "저장이 모델을 지우지 않는다" 가 그 자리를 받았습니다. skip 한 테스트는 없습니다.
- **패널 넷이 한 폼·한 버튼**입니다 — plan 은 "패널" 이라고만 적었고 저장 단위를 정하지 않았습니다.

## 남긴 것

- **H-5** — MCP Policy 허용 목록을 **읽는** 길이 없습니다. 그 결정 전까지 화면은 Policy 를 **보여주지 않습니다**(자리표시 없음).
- **`PUT /agents/{id}` 의 전제 조건 없음**(P5-4 에서 올린 틈)은 그대로입니다. 설정 패널도 읽고-쓰기이므로 같은 창이 있습니다 — 모델 칸을 한 곳으로 모은 것이 그 창을 **좁혔을 뿐** 닫지는 못합니다.
- **정의의 `policy` 블록**(타임아웃·`max_steps`·재시도·`backoff`)을 고치는 화면은 **없습니다**. 패널 넷에 들어 있지 않고, 보존만 합니다.
- **`e2e` 판정**은 **P5-9**, 캔버스는 **P5-5·P5-6**(H-1 뒤).
- 구조 테스트의 `permission` 판정은 **이름이 보이면 발화**합니다 — 화면이 Policy 를 읽게 되는 날 그 테스트가 먼저 말을 걸고, 사람이 읽기/쓰기를 구별해 고치게 됩니다.
