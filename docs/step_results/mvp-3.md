# MVP-3 — 로컬 LLM 과 모델 볼륨

**네트워크를 끊은 compose 에서 Run 하나가 로컬 모델로 `succeeded`** 가 됩니다. 그리고 **부팅 경로에 모델 다운로드가 없다**는 것이 처음으로 기계로 검사됩니다 — 볼륨이 비어 있으면 worker 가 시작 지점에서 받는 방법을 적고 멈춥니다.

## 무엇이 생겼는가

- **`scripts/fetch-model.sh`** — 네트워크 있는 환경에서 **사람이 1회**(H-3). 멱등이고(있으면 받지 않고 그렇다고 출력), 받지 못하면 0 이 아닌 코드로 끝납니다. 기본은 제품 모델 `qwen3.8:27b`, `--test-model` 은 판정용 `qwen2.5:0.5b`.
- **시작 지점의 fail-closed** — `aether_worker.main.check_model_available` 이 `openai_compatible` 일 때만 모델 서버에 **있는 모델**을 묻고(`GET /models`), 없으면 `scripts/fetch-model.sh --model <id>` 를 적은 오류로 `serve` 가 1 을 돌려줍니다. 받지는 **않습니다**.
- **`infra/docker/compose.llm.yaml`** — worker 를 `openai_compatible`·`http://llm:11434/v1` 로 돌리고 `llm` 에 `service_healthy` 로 의존. `compose.yaml` 의 기본값과 `smoke` 는 **바뀌지 않았습니다**.
- **`scripts/e2e.sh`** — `e2e` 단계의 진입점이고 **이 단위가 처음 실제 단언을 넣었습니다**: R-9(빈 볼륨이면 멈춤, 부팅이 받지 않음) · C-5(내부 전용 네트워크에서 외부로 못 나감) · R-8(차단된 네트워크에서 `succeeded`, 그리고 `llm` 로그에 `/v1/chat/completions` 가 남음).
- **`infra/docker/compose.e2e.yaml`** — `api` 의 호스트 포트를 비웁니다(`ports: !reset []`). 내부 네트워크의 포트 공개는 플랫폼마다 다르게 동작하고, 개발 스택의 8000 과도 겹치지 않습니다.

## 왜 그렇게 했는가

- **빈 볼륨 검사를 스크립트가 아니라 제품 코드에 뒀습니다.** 스크립트 선행 검사는 **그 스크립트로 띄운 경우만** 덮습니다 — 사람이 `docker compose up` 을 직접 치면 그대로 지나갑니다. 제품이 스스로 멈추는 자리가 계약입니다(DP-4).
- **`succeeded` 하나로 만족하지 않습니다.** `e2e` 는 `llm` 컨테이너 로그에 `/v1/chat/completions` 요청이 남았는지도 봅니다 — `succeeded` 만으로는 fake 어댑터로 떨어진 경우와 구별되지 않습니다(위임 범위를 넘어 구현자가 더한 것이고, 리뷰에서 받았습니다).
- **판정용 모델은 소형입니다**(spec 0006 **D-12**, 사람 2026-10-18). 제품 기본 모델은 17.7 GB·VRAM 18 GB 라 CI 러너에 올라가지 않습니다. `e2e` 는 **경로**를 단언하고 모델 품질은 보지 않습니다. 제품 기본값과 Q6 은 그대로입니다.
- **`!reset []` 과 `!override [...]` 는 다릅니다.** 프로파일을 **비우려면** `!reset []`(그래서 `llm` 이 항상 켜집니다), 포트처럼 리스트를 **바꾸려면** `!override [...]` 입니다. MVP-1 에서 이 둘을 바꿔 써 한 번 틀렸습니다.

## 정한 것과 다른 점

- **순서가 뒤바뀐 부분을 공개합니다.** 두 스크립트는 **구현이 먼저**였고(실제 Docker 로 돌려 가며 만들었습니다) 테스트를 나중에 둘렀습니다. 갈음은 **스텁 red**(함수는 아무것도 돌려주지 않고 스크립트는 `exit 0`)와 **변이 열셋**입니다. 스텁에 **빈말로 통과한 테스트 둘**("아무것도 지우지 않는다", "임시 `.env` 가 남지 않는다")도 그대로 적습니다.
- 변이 둘(M7·M11)은 **의도한 테스트가 아닌 다른 테스트**에서 먼저 발화했습니다(`pytest -x` 때문). 그 두 단언은 개별로 증명되지 않았습니다.
- **`e2e` 단계 등록은 이 PR 에 없습니다**(H-2b). plan 0006 은 "MVP-3 과 같은 PR" 로 적었지만 CC-5("하네스 변경을 제품 코드와 같은 커밋에 섞지 않는다 — 되돌리기가 한 번으로 끝나게")에 따라 **별도 PR** 로 보냅니다. H-1 도 그렇게 갔습니다.
- **리뷰에서 결함 하나를 고쳤습니다**: README 의 기동 명령에 `-p` 가 없어 프로젝트가 `docker` 가 되고, 적재는 `aether-dev` 에 들어가 **다른 볼륨**이 됐습니다. 받아 둔 모델을 눈으로 보면서 "볼륨에 없다" 를 읽게 되는 이음새입니다. 명령을 고치고 **그 이음새를 테스트로 고정**했습니다(`test_readme_starts_the_llm_stack_in_the_project_that_holds_the_model`, README 에서 `-p` 를 빼는 변이로 발화 확인).

## 남긴 것

- **제품 기본 모델(17.7 GB)로는 돌리지 않았습니다** — **H-3**(사람이 네트워크 있는 환경에서 `scripts/fetch-model.sh` 1회)입니다. 소형 모델 경로만 측정했습니다(1개 레이어 397 MB, e2e 전체 112초).
- **오프라인 CI 경로(`E2E_NO_BUILD=1` + `compose.ci.yaml`)는 fake docker 로만 덮였습니다** — 실제로 돌리지 않았습니다. CI 에 `e2e` 를 등록하는 H-2b 에서 처음 드러납니다.
- **e2e 는 끝날 때 볼륨을 지웁니다** — 그래서 매 실행이 소형 모델을 다시 받습니다(약 400 MB). CI 비용으로 남겨 둔 선택이고, 캐시는 H-2b 에서 사람이 볼 자리입니다.
- `llm` 의 pull 진행 로그에 escape 코드가 그대로 남습니다 — 걸러 내면 실패 원인이 가려지므로 두었습니다.
