# P3-3 — 검색 결과를 Context 에

Knowledge 가 모델 입력에 들어갑니다. 그리고 이 단위에서야 worker 가 **실제 Compiler 를 꽂습니다** — P3-1 이 만든 `AetherContextCompiler` 를 아무도 조립하지 않아 그때까지 `_PassthroughContextCompiler` 가 돌고 있었습니다.

## 무엇이 생겼는가

- `AgentDefinition.knowledge`(Knowledge Set **이름** 목록, 중복 거부)와 `knowledge_top_k`(`None` 이면 5). **새 HTTP 경로는 없습니다** — 기존 `PUT /agents/{id}` 가 새 Version 을 만듭니다(D-5).
- `aether_context` 의 `KnowledgeSearch` outbound 포트와 pgvector 어댑터(`adapters/outbound/knowledge_search/postgres.py`). 이름 → id 해석과 질의 임베딩을 어댑터가 맡습니다 — 조립 유스케이스는 DB 도 임베딩도 모릅니다.
- `domain/knowledge.py` 의 `render_knowledge_block` — `[knowledge source=<경로> chunk=<순번> trust=untrusted]…[/knowledge]`.
- `CompileContextUseCase` 의 Knowledge 소스: 질의는 `conversation` 의 마지막 `user` 메시지, 결과는 **독립된 메시지 하나**로 system 다음·conversation 앞에. `ContextReport.source_tokens` 에 `knowledge` 가 채워집니다.
- `apps/worker/src/aether_worker/main.py` 의 `_build_production_handler` 가 `AetherContextCompiler(CompileContextUseCase(CharApproxTokenCounter(), PostgresKnowledgeSearch(...)))` 를 꽂습니다.

## 왜 그렇게 했는가

- **검색 결과는 `Observation` 과 같은 취급입니다**(spec 2.5, D-8). `render_observation`(spec 0002 P1-4)과 같은 모양의 표지를 쓰고, system 메시지에 섞지 않습니다 — 섞으면 신뢰 경계 밖의 문장이 지시로 읽힙니다.
- **출처 없는 청크는 넣지 않습니다.** 출처 없는 사실은 검증할 수 없습니다.
- **이름의 존재는 생성 시 검증하지 않습니다.** `tools`(spec 0003 D-16)와 같은 방식으로 중복만 막고, 없는 이름은 검색 시점에 조용히 0건입니다 — 바인딩되지 않은 집합은 검색되지 않는다는 R-9 이 같은 코드로 성립합니다.
- **상위 k 기본값 `5` 가 네 곳에 흩어져 있었습니다.** `aether_runtime` 쪽 셋과 어댑터 시그니처는 `DEFAULT_KNOWLEDGE_TOP_K` 하나에서 오게 했습니다. `aether_context` 쪽 둘은 AR-3 때문에 import 할 수 없어 숫자를 맞추고 주석이 서로를 가리킵니다 — 이 중복은 **의도된 것이고 주석이 그 사실을 적습니다**.

## 정한 것과 다른 점

- **spec 2.5 의 "청크 id"** 를 `(source_path, chunk_index)` 쌍으로 렌더링했습니다. `data.knowledge_chunks` 에 UUID `id` 가 있지만 `SearchResult` 가 싣지 않습니다. 재적재가 교체이므로 UUID 는 적재마다 바뀌고, 사람이 되짚을 수 있는 출처는 경로와 순번입니다. 다른 형식을 원하면 spec 2.5 를 고치고 이 렌더링을 따라오게 합니다.
- plan 과 제 브리프가 `_build_production_executor` 라고 적은 함수는 실제로 `_build_production_handler` 입니다.
- **순서를 어긴 단언 셋**이 있었습니다 — 어댑터와 전체 경로 통합 테스트는 구현 뒤에 썼고, API 의 Version 테스트는 첫 실행부터 통과했습니다(새 코드가 필요 없다는 plan 의 예측과 같습니다). 앞의 둘은 사후 변이 주입으로 검증하고 받았습니다.
