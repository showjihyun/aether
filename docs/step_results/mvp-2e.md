# MVP-2e — 대화 화면, 그리고 그것이 대화가 아니라는 사실

`/agents/{id}/chat` 이 생겼습니다. 입력을 보내면 Run 이 시작되고 모델의 답변이 **도착하는 대로** 쌓입니다 — MVP-2d 가 `model.delta` 를 흘리게 했으니 그릴 것이 처음으로 존재합니다. `/agents` 목록의 이름 칸이 여기로 들어오는 길이고, 그 링크는 MVP-2a 가 "목적지가 생길 때" 로 미뤄 둔 것입니다.

그런데 이 화면의 절반은 **그것이 대화가 아니라는 사실을 말하는 일**입니다.

## 무엇이 생겼는가

| 조각 | 내용 |
| --- | --- |
| `app/agents/[id]/chat/page.tsx` | 서버 컴포넌트. 키가 없으면 `MissingApiKey`, Agent 가 없으면 `DetailError`(404 분기, MVP-2c 가 만든 것). `Chat` 에 `agentId`·`agentName`·`memoryEnabled` 만 넘깁니다 — **키는 넘기지 않습니다** |
| `app/agents/[id]/chat/actions.ts` | `"use server"` 의 `startRun(agentId, input)`. 입력·id 모양을 **서버에서** 검사하고 키로 `runAgent` 를 부릅니다. 예외를 던지지 않고 `{ok:true,runId}` / `{ok:false,message}` 로 돌려줍니다 |
| `app/agents/[id]/chat/Chat.tsx` | 클라이언트. 보낸 것마다 항목 하나, 그 Run 의 스트림을 **중계 경로로 키 없이** 열어 `model.delta` 를 이어 붙입니다. 상태 `badge`, 끊김 표시, 도구 호출 이름 한 줄, `/runs/{id}` 로 가는 "타임라인 보기" |
| `app/agents/page.tsx` | 이름 칸이 `/agents/{id}/chat` 링크입니다 |

## 왜 그렇게 했는가

**쓰기는 중계를 지나지 않습니다**(**D-18**, 사람 2026-10-18). plan 은 원래 "대화가 `POST /agents/{id}/run` 을 허용 목록에 더한다" 고 적었습니다. 사람이 **서버 액션**을 골랐고, 그래서 중계는 **`GET` 넷 그대로**입니다 — 중계가 본문을 통과시키는 구멍이 생기지 않고 요청 모양을 web 이 소유합니다. 노출 수준은 같습니다(세션이 없으므로 web 에 닿는 사람은 Run 을 시작할 수 있습니다 — 그 선은 Phase 8). `GET /agents/{id}` 도 허용 목록에 넣지 않았습니다: 그 호출은 서버 컴포넌트가 키로 직접 합니다.

**서버 액션은 브라우저가 직접 때릴 수 있는 진입점**이므로 인자를 신뢰하지 않습니다 — id 모양, 빈 입력, 10,000자 상한을 서버에서 봅니다. 실패 메시지에는 키 값도 `AETHER_API_URL` 도 업스트림 본문도 넣지 않고, 분기는 `AetherHttpError.status` **필드**로 합니다(문구를 파싱하지 않습니다). 401·403 은 중계와 **같은 말**을 합니다("키를 다시 발급해 주입하세요") — 두 경로가 같은 상황에서 다른 말을 하면 다음 행동이 갈립니다(MVP-2p 리뷰의 교훈).

## 정한 것과 다른 점

**DESIGN 5절의 "좌: 대화, 하: 입력" 을 좌우로 나누지 않았습니다.** 목록 하나와 입력 하나뿐이라 나눌 것이 없습니다 — 위아래로 뒀고 DESIGN 을 그에 맞게 고쳤습니다.

**"무엇이 이어지는가" 한 줄이 화면 맨 위에 있습니다.** 이것은 plan 에 없던 요구입니다. `POST /agents/{id}/run` 의 본문은 `{ input, agent_version? }` 이고 **이력을 받는 자리가 없습니다** — 각 입력은 독립 Run 이고 모델은 이전 **질문**을 보지 못합니다. 다만 `memory_enabled` 인 Agent 는 Run 이 **`succeeded`** 로 끝날 때 그 **답변**이 Memory 에 남고 다음 Run 의 Context Compiler 가 포함합니다. 그러니 "이어진다/안 이어진다" 가 둘 다 틀리고, 화면은 그 플래그로 **두 경우를 갈라** 말합니다. 각 문장을 테스트가 고정합니다.

**리뷰에서 둘 고쳤습니다.** (1) 그 문구에 **조건이 빠져 있었습니다** — "이전 답변은 Memory 로 남습니다" 는 실패한 Run 의 답변도 남는다고 읽힙니다. `_remember` 는 `succeeded` 일 때만 불립니다. "성공으로 끝난 실행의 답변만" 으로 고쳤습니다. 이 화면의 존재 이유가 "이어지는 것처럼 보이지만 아닌 것" 을 바로 말하는 것이므로 그 절반이 틀리면 안 됩니다. (2) 상태 코드가 **있는** 실패에 "api 에 닿지 못했습니다" 라고 말하고 있었습니다 — 상태 코드가 왔다는 것은 닿았다는 뜻입니다(429·422·500). MVP-2c 의 `/knowledge/{id}` 404 와 같은 결함이라 상태 코드를 밝히는 말로 갈랐고, 그 자리의 옛 기대를 고정하던 테스트도 새 사실로 고쳤습니다.

**중계 허용 목록에 "전부 `GET`" 단언을 한 줄 더했습니다.** 타입 리터럴이 컴파일 시점에 막지만, 이 PR 의 주장 자체가 "넓히지 않았다" 이므로 실행 시점 증거를 둡니다.

## 남긴 것

- **이력을 받는 API 가 없습니다.** 여러 턴을 모델에 전달하려면 `POST /agents/{id}/run` 이 이력을 받거나 Thread 개념이 필요하고, 그것은 이 단위 밖입니다(Agent Builder·Phase 5 이후). 지금은 화면이 그 사실을 말하는 것으로 처리했습니다 — **사람이 볼 자리**입니다.
- **R-5 는 여전히 `e2e` 가 봅니다.** 여섯 경로(+대화)가 실제 스택에서 뜨는지는 MVP-4 입니다.
- 재전송하면 앞 항목의 스트림을 닫습니다. 그 항목에는 "다른 입력을 보내 이 실행의 스트림을 닫았습니다 — 타임라인 보기" 를 남깁니다(끊김으로 적으면 거짓입니다).
- 입력 상한은 UTF-16 코드 유닛 10,000 입니다(이모지는 2로 셉니다). api 쪽 상한과 맞춘 값이 아니라 화면이 정한 값입니다.
