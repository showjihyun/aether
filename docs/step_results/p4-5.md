# P4-5 — LLM / MCP / TOOL 노드

Agent 를 거치지 않고 **한 번** 부르는 노드 셋입니다. 노드 종류가 다 찼고 Phase 4 의 마지막 단위입니다. 이 단위에서 가장 값있는 것은 코드가 아니라 **막혔던 두 자리**입니다 — 권한 주체와 감사. 둘 다 사람이 결정했습니다.

## 무엇이 생겼는가

- **세 노드** — `LLM`(`{"text","finish_reason"}`), `TOOL`·`MCP`(`{"content","is_error"}`). 파킹하지 않고 출력은 P4-2b 의 상한을 그대로 받습니다.
- **포트 둘** — `ModelInvoker`·`ToolInvoker`. 어댑터는 `apps/worker` 에 있고 조립은 `main.py` 뿐입니다(AR-10). 기존 `_build_model_gateway`·`_build_tool_gateway` 를 **재사용**합니다.
- **노드 설정 여섯 키** — `llm_prompt`·`llm_prompt_path`, `tool_server`·`tool_name`·`tool_arguments`·`tool_arguments_path`. 경로는 `CONDITION` 과 **같은 맥락**을 가리킵니다.
- **저장 때 거부 둘** — `llm_node_without_prompt`·`tool_node_without_target`. 사유 **열네 개**.
- **실패 사유 셋** — `model_call_failed`·`tool_call_denied`·`tool_call_failed`.
- **마이그레이션 0010** — 감사의 `run_id` FK 제거 + `run_kind`.

## 왜 그렇게 했는가

- **통로를 새로 만들지 않았습니다.** 모델은 `ModelGateway`(AR-5), 도구는 MCP Gateway(AR-6)를 지납니다 — Gateway 를 우회하는 경로를 만들면 Firewall(Phase 10)이 관측하지 못합니다(DP-2). `aether_workflow` 는 포트만 선언하고 `.importlinter` 의 ignore 목록을 **늘리지 않았습니다**.
- **`MCP` 와 `TOOL` 을 같게 다룹니다** — 모든 도구 호출이 MCP Gateway 를 지나므로 구현이 같습니다. `HUMAN`·`APPROVAL` 과 같은 근거입니다.
- **템플릿 언어를 만들지 않았습니다** — 리터럴 + **선언된 경로** 하나씩입니다. 임의 표현식을 평가하지 않는다는 D-9 의 정신을 그대로 씁니다.
- **권한 주체는 노드가 지목한 Agent 입니다**(개정 9, **사람 결정**). Policy 는 `agent_version_id` 로만 판정하고 그 열에 `control.agent_versions` FK 가 있어 Workflow Version 을 주체로 쓸 수 없습니다. 대안(Policy 를 Workflow 까지 확장)은 보안 변경이라 사람에게 올렸고, 고른 쪽은 **Policy 를 건드리지 않습니다**. 기본 deny 가 그대로이고 권한이 없으면 노드가 `tool_call_denied` 로 실패합니다.
- **감사가 조용히 사라지고 있었습니다**(개정 10, **사람 결정**). `data.tool_call_audit.run_id` 가 `NOT NULL` + `control.runs` FK 이고 감사 쓰기 실패는 **삼켜지므로**(spec 0003 D-10), Workflow 의 도구 호출은 **성공하고 기록만 없어졌습니다.** 0010 이 FK 를 풀고 `run_kind` 를 더해 어느 평면의 Run 인지 남깁니다. 되돌리기는 감사 행을 잃으므로 그 사실을 마이그레이션에 적었습니다.

## 정한 것과 다른 점

- **`run_kind` 를 `ToolGateway.call()` 인자가 아니라 어댑터 인스턴스의 성질로 뒀습니다** — 포트 인자로 넣으면 기존 fake 16곳이 깨집니다. Agent Run 호출부는 **한 줄도 바뀌지 않았습니다**.
- **`tool_server` 가 서버 표의 키이자 Policy 의 `server_name`** 입니다 — v1 에서 둘을 다르게 둘 수 없습니다.
- **도구 노드의 재시도는 at-least-once 입니다** — 시작 뒤 끝나기 전에 죽으면 다시 부릅니다. 부작용이 있는 도구는 두 번 실행될 수 있습니다(재시도 보장이 아닙니다).
- **인자 경로가 객체가 아니면** `condition_type_mismatch` 를 재사용합니다.
- 포트가 꽂히지 않은 종류는 `unsupported_node_kind` 로 **시끄럽게** 실패합니다.
- **red 순서가 일부 뒤바뀌었습니다** — 통합 테스트는 프로덕션 배선을 보고 쓴 것이라 구현 뒤에 초록이 됐고, 변이 다섯으로 갈음했습니다.

## 남긴 것

- **감사 쓰기 실패를 삼키는 성질(spec 0003 D-10)은 그대로입니다.** 이번 변경으로 실패할 이유가 없어졌을 뿐, 다른 이유로 실패하면 여전히 조용합니다 — 그 자체가 후보로 남을 만합니다.
- **감사 행의 참조 무결성을 DB 가 보증하지 않습니다**(FK 제거의 대가). `run_id` 가 실재하는지는 애플리케이션이 책임집니다.
- 실제 LLM 으로 8 KiB 초과 응답·수동 compose 확인은 하지 않았습니다(fake 로 대체).
- **H-2(D-8 되돌리기 판단)에 넘길 숫자**: 노드 출력의 소비자는 여전히 **`CONDITION` 하나**입니다. 크기 분포는 실제 Workflow 를 돌린 뒤에 모으는 것이 맞습니다.
