# P5-2 — 노드 실행 조회 API 와 SDK

P5-1 이 만든 투영이 **읽힙니다.** `GET /workflow-runs/{id}/nodes` 하나와 SDK 함수 하나이고, 이 단위의 전부는 "api 역할로 노드 상태가 나온다 — `data` 는 보지 않는다"(spec 0007 R-5 의 나머지 절반)입니다. 화면은 P5-3 입니다.

## 무엇이 생겼는가

- **경로 하나** — `GET /workflow-runs/{id}/nodes`. `200 { items: [{ node_id, kind, status, started_at, finished_at, failure_reason }], next_cursor }`, 노드가 없는 Run 은 **200 + 빈 목록**, 없는 Run 은 `404 workflow_run_not_found`, 깨진 커서는 `422 invalid_cursor`, 인증 없으면 401. 페이지 규칙은 `GET /agents` 를 그대로 베꼈습니다(`limit` 기본 50, 1~200).
- **api 의 자리들** — `domain/workflow_node_state.py`(읽기 값 객체), `application/ports/inbound/workflow_run_nodes.py`, `application/ports/outbound/workflow_node_state_reader.py`, `application/usecases/list_workflow_run_nodes.py`, `adapters/inbound/http/workflow_run_nodes.py`(새 라우터), 그리고 P5-1 의 스토어에 더한 `list_for_run`.
- **SDK** — `listWorkflowRunNodes(workflowRunId, params?)` 와 `ListWorkflowRunNodesResponse`. `openapi.json` 은 **추가만**(+175/−0: 경로 하나, 스키마 셋, 기존 경로·스키마 변경 0건).
- **문서** — [api.md](../api.md) 5.1(목록 표와 커서 문구)·6절(`aether:workflow_node_states:status`)·9절(조회 절), [data-model.md](../data-model.md)(`control.workflow_node_states` 표 절, 마이그레이션 0012, 그리고 **문서에 없던 0011**).
- 마이그레이션과 `GRANT` 는 **0건**입니다.

## 왜 그렇게 했는가

- **정렬은 `node_id` 오름차순입니다.** `GET /agents` 는 `(시각, id)` 로 정렬하지만 이 표에는 생성 시각이 없습니다. `started_at` 은 `NULL` → 값으로 **변할 수 있고** `status_seq` 는 상태가 바뀔 때마다 변하므로, 그 둘에 키셋 커서를 걸면 쪽 사이에서 행이 빠지거나 겹칩니다. `node_id` 는 불변이고 노드당 한 행이라 안정적입니다 — 실행 순서가 필요한 화면은 P5-3 이 받은 쪽에서 정렬합니다.
- **새 라우터 파일입니다.** `build_listings_router` 의 시그니처와 그 테스트를 건드리지 않는 쪽이 additive 규칙에 맞습니다(spec 0006 D-11 과 같은 선).
- **읽기 포트를 쓰기 포트와 나눴습니다.** 상태 소비자(`WorkflowNodeStateProjectionStore`)와 조회(`WorkflowNodeStateReader`)가 서로의 메서드를 모르게 둡니다 — 기존 포트를 넓혔다가 `api-typecheck` 가 fake 들에서 발화한 것이 그 자리에서 드러났고, 넓히지 않는 쪽으로 되돌렸습니다.
- **`status_seq` 는 응답에 없습니다.** 투영의 멱등 기준이지 화면의 값이 아닙니다. 내보내면 그것에 기대는 소비자가 생기고 투영의 내부 사정이 제품 계약이 됩니다.
- **`output` 은 없습니다**(D-4). 투영에도 없고, 그래서 이 경로가 `aether_control` 로 통과하는 것 자체가 평면을 지켰다는 증거입니다(`GET /workflow-runs` 와 같은 선).

## 정한 것과 다른 점

- **정렬 키**가 plan 의 "`GET /agents` 를 그대로 베낀다" 를 글자대로 따르지 않습니다 — 페이지 **규약**(쿼리·응답·오류)은 같고 **정렬 키**만 `node_id` 입니다. 위의 첫 항목이 이유입니다.
- **라우터를 `listings.py` 에 넣지 않았습니다** — plan 은 자리를 지정하지 않았고, 기존 팩토리를 건드리지 않는 쪽을 골랐습니다.
- 그 둘 말고는 plan 0007 2절의 P5-2 표와 같습니다.

## 남긴 것

- **화면은 P5-3** 입니다. 지금 이 경로를 부르는 제품 코드는 없습니다 — SDK 함수와 테스트뿐입니다.
- **회차(`iteration`)는 여전히 보이지 않습니다** — 투영이 노드당 한 행입니다(P5-1 의 `남긴 것`).
- **`docs/data-model.md` 에 마이그레이션 0011 절이 없던 것**은 이번 단위와 무관한 기존 불일치였고, 같은 파일을 여는 커밋이라 함께 적었습니다.
