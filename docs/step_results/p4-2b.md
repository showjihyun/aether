# P4-2b — 노드 출력과 CONDITION 분기

Workflow 가 **갈라집니다.** 같은 정의가 입력에 따라 다른 경로를 타고(R-5), `AGENT` 노드는 자식 Run 의 답을 상한 있는 출력으로 남깁니다. spec 이 스스로 "확신이 가장 낮다" 고 적은 결정(D-8)의 단위이고, 되돌리는 조건(C-3)을 흐리지 않는 것이 이 단위의 절반입니다.

## 무엇이 생겼는가

- **노드 출력** — `domain/node_output.py`. `AGENT` 노드의 출력은 `{"text": <자식의 마지막 assistant 본문>, "status": <자식의 종결 상태>}` 이고 상한은 **직렬화된 UTF-8 바이트** 기준 `AETHER_WORKFLOW_NODE_OUTPUT_MAX_BYTES`(기본 8192, 최소 64)입니다. 넘기면 본문만 잘라 `output_truncated` 를 함께 적습니다. 본문은 `data.run_states` 에서 읽습니다(worker 가 소유하는 평면 — 새 권한이 없습니다).
- **`CONDITION`** — `domain/condition.py` 의 **순수 함수** `evaluate_condition` 과 연산자 여섯(`equals`·`not_equals`·`contains`·`gt`·`lt`·`exists`). 판정 대상은 선언된 맥락 하나(`input`·`nodes.<id>`)이고, 분기는 간선 `label` 의 `true`/`false` 입니다.
- **저장 때 거부 둘** — `condition_node_without_predicate`·`condition_node_without_both_branches`. 사유가 아홉 → **열한 개**입니다.
- **실패 사유 둘** — `condition_path_missing`·`condition_type_mismatch`.
- **구조 테스트** — `tests/arch/test_workflow_output_stays_in_data.py`. 출력에서 파생된 값이 발행·통지·페이로드·로깅 호출의 인자로 들어가면 실패하고, 출력을 읽는 자리의 목록을 고정합니다.
- api 정의 표면의 세 키와 SDK(연산자 열거형 포함), 설정 세 곳(`settings.py`·`.env.example`·`compose.yaml`). **마이그레이션은 없습니다** — 출력 열은 0005 가 만들어 뒀습니다.

## 왜 그렇게 했는가

- **판정 대상을 선언된 맥락 하나로 고정했습니다.** "직전 노드의 출력" 같은 암묵 규칙은 그래프를 고칠 때 **조용히 뜻이 바뀝니다.** 경로가 `nodes.<id>` 를 명시하면 그래프와 판정식이 같은 이름을 가리킵니다.
- **없는 경로는 조용한 거짓이 아닙니다.** `exists` 만 거짓이고 나머지는 실행 실패입니다. 조용히 한쪽으로 가는 Workflow 는 **디버깅할 수 없습니다** — 로그에 아무 것도 남지 않고 결과만 다릅니다.
- **분기 한쪽만 선언된 그래프를 저장 때 거부합니다.** 실행 중에 발견하면 이미 자식 Run 을 띄운 뒤입니다.
- **판정을 순수 함수로 뒀습니다**(AR-9). DB 없이 여섯 연산자와 두 실패를 다 판정하고, 재개 때 다시 불러도 같은 맥락이면 같은 결과입니다 — 그래서 분기 결과를 영속하지 않습니다.
- **`gt`·`lt` 에 불리언을 숫자로 취급하지 않습니다.** Python 의 `True == 1` 이 판정에 새면 `equals 1` 이 `true` 와 같아집니다.
- **본문만 자르고 `status` 는 줄이지 않습니다.** `status` 는 판정에 쓰이는 값이고, 상한이 틀보다 작아도 빈 본문 + `truncated` 로 남깁니다.
- **노드 실행 조회 API 를 만들지 않았습니다.** api 역할은 `data` 에 **아무 권한이 없습니다**(0001 R-7). 조회를 만들려면 노드 실행을 `control` 로 투영해야 하고 그것은 화면이 생기는 Phase 5 의 일입니다. 덕분에 **출력의 소비자가 하나**(`CONDITION`)뿐이고 C-3 의 되돌리기가 쌉니다.

## 정한 것과 다른 점

- **openapi 변경이 "세 키 추가" 로 끝나지 않았습니다** — 연산자를 `str` 이 아니라 **열거형**으로 받아서 스키마 컴포넌트 하나가 늘었습니다. 잘못된 연산자가 `422` 로 걸리는 쪽이 실행 중에 터지는 것보다 낫습니다.
- **`equals null` 을 표현할 수 없습니다** — `condition_value` 의 `null` 은 "값 없음" 으로 읽습니다. 필요해지면 `is_null` 연산자를 더하는 쪽이지, `null` 의 뜻을 둘로 쓰지 않습니다.
- **경로에 배열 인덱스가 없습니다.** 객체 키만 따라갑니다. 노드 id 에 `.` 이 있으면 그 노드의 출력은 가리킬 수 없고, 그 경우 실행은 `condition_path_missing` 으로 **시끄럽게** 실패합니다.
- **상한에 최소값 64 를 걸었습니다**(plan 에 없음). 봉투조차 담지 못하는 설정은 오류입니다.
- **기존 테스트의 예시를 바꿨습니다** — "지원하지 않는 노드 종류" 의 예가 `CONDITION` 이었고 이제 지원하는 종류라 `WAIT` 로, `agent_id` 무시를 보던 테스트는 `LLM` 으로 옮겼습니다. 지운 테스트는 없습니다.
- **red 순서가 일부 뒤바뀌었습니다** — 포트 시그니처와 DB 어댑터, 사슬 통합 3건, 구조 테스트는 구현 뒤에 썼습니다. 그 부분의 근거는 변이 셋입니다(PR 본문).

## 남긴 것

- **로컬 LLM 으로 8 KiB 초과 응답을 보지 못했습니다**(plan 4절의 추가 확인). fake 모델의 긴 응답(`"가"×5000`)으로 대체했고 그 사실을 미측정으로 적습니다.
- **compose 에서 새 환경변수가 worker 에 실제로 전달되는지 확인하지 않았습니다** — 변수는 세 곳에 넣었고 통합 테스트는 설정을 직접 주입합니다.
- 분기 결과를 영속하지 않습니다. 재개는 순수 함수로 다시 판정합니다 — 같은 맥락이면 같은 결과이지만, 맥락이 바뀔 수 있는 노드 종류(`LOOP`)가 생기면 다시 봐야 합니다.
- **H-2(D-8 되돌리기 판단)의 숫자 — 2026-10-17 에 실제 스택에서 측정했습니다.** 출력의 소비자는 **1곳**(`CONDITION`)이고, 크기는 다음과 같습니다.

| Run | `text` 바이트 | 애플리케이션 기준 합계 | 잘림 |
| --- | --- | --- | --- |
| 평범한 입력 | 45 | 77 (상한의 **0.9%**) | 아니오 |
| 한글 9,000자 입력 | 8,157 | **8,189 ≤ 8192** | **예** |

두 번째 행이 상한의 동작을 증명합니다 — 이진 탐색이 **상한에 들어가는 가장 긴 접두사**를 정확히 골랐습니다(8,192 보다 3바이트 아래).

**측정 함정 하나**: SQL 로 `octet_length(output::text)` 를 재면 **8,195** 가 나와 상한을 넘은 것처럼 보입니다. jsonb 를 다시 렌더링할 때 PostgreSQL 이 `:`·`,` 뒤에 공백을 넣기 때문이고, 애플리케이션의 compact 직렬화(`separators=(",", ":")`)와 **다른 측정**입니다. **결함이 아닙니다** — 모르고 "상한이 깨졌다" 며 고치러 들어가지 않도록 적어 둡니다.
