# MVP-2a — 목록 화면 둘(`/agents`·`/runs`)

**사이드바를 눌러 무언가가 나옵니다.** 이 단위 전까지 사이드바의 다섯 항목은 **전부 404** 였습니다 — API 와 SDK 는 MVP-0 에서 이미 섰는데(PR #163) 그것을 보는 화면이 없었습니다.

## 무엇이 생겼는가

- **`/agents`** — 이름, 현재 Version(`badge` `outline`), 수정 시각. `listAgents`.
- **`/runs`** — 상태 `badge`(`RunStatusBadge` 재사용), Agent, 시작, 소요. `listRuns`.
- **세 상태를 공유 부품으로** — `ListEmpty`·`ListError`·`LoadMore`·`TableSkeleton`(`components/ListStates.tsx`). 2b·2c 가 같은 모양을 다시 만들지 않게 한 자리에 뒀습니다.
- **표현 부품 둘** — `CopyableId`(앞 8자 + `…`, 클릭 복사), `RelativeTime`(상대 시간 + `title` 에 ISO). 규약은 DESIGN 6절입니다.
- **R-6 테스트** — `NAV_ITEMS` 에서 `href` 를 **수집해** 라우트 존재를 봅니다. 지금은 셋이 없어 `it.fails`(skip 아님)입니다.
- **SDK 에 `AetherHttpError`** — 2xx 가 아닌 응답의 **상태 코드를 필드로** 올렸습니다(additive, 메시지 문구 불변).

## 왜 그렇게 했는가

- **행을 클릭 가능하게 만들지 않았습니다.** 목적지가 아직 없습니다(`/runs/{id}` 는 2b, 대화는 2c). 404 로 가는 링크를 심는 것보다 클릭이 안 되는 행이 정직합니다(DESIGN 9절). 링크가 **0개**임을 테스트가 고정합니다.
- **상태 코드를 메시지에서 파싱하지 않습니다.** DESIGN 7.1 은 `422` 에만 "처음부터 보기" 를 내보내라고 정합니다. SDK 는 상태를 사람이 읽는 문구에만 담고 있었고, 화면이 그것을 정규식으로 읽으면 **SDK 가 문구를 바꾸는 순간 분기가 조용히 깨집니다** — 그리고 화면 테스트가 같은 문자열을 손으로 베껴 쓰므로 **아무 테스트도 그것을 잡지 못합니다**. 그래서 SDK 쪽을 고쳤습니다.
- **오류의 첫 문장은 할 수 있는 일**이고 `aether-sdk: GET /runs?cursor=… failed with status …` 는 `details`("기술 정보", 닫힘) 안에 있습니다. 원문을 그대로 보이면 사용자가 할 수 있는 일이 아무것도 적혀 있지 않습니다.
- **"다음 쪽" 이지 "더 보기" 가 아닙니다.** `?cursor=` 로 **쪽을 교체**합니다 — 이어 붙이려면 클라이언트 상태가 필요하고, DESIGN 7.1 이 무한 스크롤을 거부한 이유(스크롤 복원·키보드 접근성·"끝" 표시)가 그대로 돌아옵니다. 링크이므로 **뒤로 가기가 이전 쪽**이고 새 규약이 필요하지 않습니다.
- **빈 첫 쪽에는 버튼을 두지 않습니다.** DESIGN 7절이 "다음 행동 `button` 하나" 를 요구하지만 생성 화면이 MVP 범위에 없어 **갈 곳이 없습니다**. 반면 **커서 쪽이 비면** 막다른 길이므로 "처음부터 보기" 를 붙입니다.
- **`/runs` 의 Agent 열은 짧은 ID 입니다.** `RunSummary` 에 이름이 없습니다 — 이름을 보이려면 N+1 호출이나 목록 응답 변경이고 둘 다 이 단위 밖입니다.
- **`force-dynamic` 유지** — 정적 프리렌더가 빌드 때 api 를 부르면 `web-build` 가 api 없이 실패합니다(홈 화면의 선례).

## 정한 것과 다른 점

- **SDK 를 건드렸습니다.** 위임 범위에서 `packages/sdk` 를 제외했는데, 리뷰에서 상태 코드 계약의 문제를 찾아 주 세션이 직접 고쳤습니다. additive 이고(메시지·`instanceof Error` 불변) SDK 테스트가 그 계약을 **출처에서** 고정합니다.
- **DESIGN.md 를 네 줄 고쳤습니다** — "다음 쪽" 라벨, 빈 결과의 예외, 오류의 접힘, `/runs` 의 Agent 열. 화면이 정한 것을 문서에 되돌려 적는 자리입니다(그 문서의 "갱신하는 때" 표).
- **`/settings` 가 2c 로 들어왔습니다**(spec 0006 **D-13**, 개정 2). R-6 과 DESIGN 5절이 서로 모순인 것이 이 단위 직전에 드러났습니다 — 에이전트는 사이드바에서 빼는 쪽을 추천했고 사람이 **화면을 만드는 쪽**을 골랐습니다.
- **red 순서가 일부 뒤바뀌었습니다** — 표현 부품(`lib/format`·`CopyableId`·`RelativeTime`)은 구현과 테스트가 함께 갔고, 화면과 SDK 계약은 테스트가 먼저였습니다(`Failed to resolve import "./loading"`, `No "AetherHttpError" export`). 뒤바뀐 쪽은 변이로 갈음했습니다.

## 남긴 것

- **브라우저로 직접 열어 보지 않았습니다.** plan 의 "네 경로 직접 열기 1회" 는 2c 가 네 경로를 다 채운 뒤의 사람 손입니다. 지금 증거는 `web-unit`·`web-build` 뿐입니다.
- **다크 모드·반응형을 눈으로 확인하지 않았습니다**(DESIGN 8절). 토큰만 쓰고 색을 하드코딩하지 않았으므로 구조적으로는 따라오지만, 그것은 **미측정**입니다.
- **`CopyableId` 의 복사 동작과 tooltip 에 테스트가 없습니다** — 짧은 ID 렌더만 봅니다. 클립보드는 jsdom 에서 따로 꽂아야 합니다.
- **R-6 은 아직 거짓입니다** — `/knowledge`·`/workflows`·`/settings` 가 없습니다. 2c 가 셋을 채우면 `it.fails` 가 **스스로 깨지므로** 제거를 잊을 수 없습니다.
- **빈 커서 쪽을 api 가 실제로 주는지 확인하지 않았습니다.** 그 화면은 만들었지만(막다른 길을 없애려고) 어떤 입력이 그 응답을 내는지는 `e2e` 가 볼 영역입니다.
