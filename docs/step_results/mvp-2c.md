# MVP-2c — 사이드바의 마지막 404 셋, 그리고 문서가 요구한 없는 값 둘

사이드바가 가리키던 **404 셋**(`/knowledge`·`/workflows`·`/settings`)이 없어졌습니다. spec 0006 **R-6**("사이드바의 링크에 404 가 없다")이 MVP-2a 에서 의도된 빨강(`it.fails`)으로 세워진 뒤 세 단위를 기다렸고, 이 단위에서 **참이 됐습니다**. 같이 드러난 것이 하나 더 있습니다 — DESIGN.md 가 화면에 요구한 값 둘이 **API 에 없었습니다**. 하나는 열을 지워 끝났고, 다른 하나는 화면 하나를 이 단위에서 **빼게** 했습니다.

## 무엇이 생겼는가

| 경로 | 내용 |
| --- | --- |
| `/knowledge` | 세트 목록(이름·생성). 이름을 누르면 그 세트의 적재로 갑니다 |
| `/knowledge/{id}` | **그 세트의 적재 목록**(source·상태·요청·소요, `failure_reason`). 없는 세트는 404 분기로 "찾을 수 없습니다" + 목록으로 |
| `/workflows` | 표 둘 — 정의(이름·현재 Version·수정)와 실행(상태·현재 노드·**기다리는 대상**·요청). 커서가 둘이고 한쪽 "다음 쪽" 이 상대편 커서를 지킵니다 |
| `/settings` | card 셋 — 테마, 연결(`/healthz` 의 status·service·version + **브라우저 api 주소** `/api/aether`), 키 발급 안내(CLI 명령 한 줄) |

컴포넌트 넷이 늘었습니다 — `WorkflowRunStatusBadge`·`IngestionStatusBadge`(새 enum 둘), `DetailError`(하나를 여는 화면들의 404 분기를 `/runs/{id}` 와 공유), 그리고 `ListStates` 의 `isNotFound`. `LoadMore` 는 이미 쿼리가 붙은 주소와 **쿼리 이름**을 받게 넓혔습니다(`/workflows` 의 표가 둘이기 때문입니다) — `/agents`·`/runs` 의 주소는 글자까지 그대로이고 그 사실을 테스트로 고정했습니다.

## 왜 그렇게 했는가

**적재를 하위 경로로 뺐습니다.** DESIGN 5절은 `/knowledge` 한 화면에 "세트 목록 + 적재 상태" 를 적었지만 적재 API 는 **세트별 경로**(`GET /knowledge-sets/{id}/ingestions`)입니다. 목록에서 세트마다 부르면 N+1 이고, 그것은 `/runs` 가 Agent 이름을 뺀 것과 같은 이유로 거절할 일입니다. 그래서 `/runs` → `/runs/{id}` 와 같은 모양으로 갈랐습니다.

**없는 세트의 404 를 일반 오류로 두지 않았습니다.** 리뷰에서 걸렸습니다 — 위임된 구현은 404 에도 `ListError` 의 "api 가 떠 있는지 확인한 뒤 새로고침" 을 보였습니다. 그 지시는 **떠 있는 api** 에 대해 틀립니다(api 는 그 경우 404 `knowledge_set_not_found` 를 줍니다). 같은 저장소의 `/runs/{id}` 가 이미 상태 코드 필드로 그 분기를 하고 있었으므로, 그 코드를 `DetailError` 로 올려 둘이 함께 쓰게 했습니다.

**기다리는 대상에 라벨을 붙였습니다.** 이것도 리뷰에서 걸렸습니다. `waiting_run_id` 와 `waiting_node_execution_id` 는 둘 다 짧은 mono id 로 그려져 **구별되지 않았고**, 상태 badge 도 갈라주지 않습니다(`waiting_approval` 이 노드 실행 id 와 함께 옵니다). 보는 사람이 다음에 열 곳이 달라지므로 라벨이 정보입니다.

**`/settings` 는 키를 모릅니다.** 환경변수 값을 어느 것도 찍지 않습니다 — `AETHER_API_KEY` 도, 서버 쪽 `AETHER_API_URL` 도 아닙니다(내부 주소이고 키 주변 정보입니다). 보이는 주소는 브라우저가 실제로 쓰는 `/api/aether` 입니다(D-15). `/healthz` 는 인증이 필요 없으므로 **키가 없어도 이 화면은 뜹니다**. 테스트가 그 셋을 고정합니다(가짜 키·가짜 내부 주소를 넣고 본문과 `innerHTML` 양쪽에 없음을 단언).

## 정한 것과 다른 점

**대화 화면을 만들지 않았습니다.** plan 은 이 단위에 "Agent 대화(입력 → `POST /agents/{id}/run` → 스트림)" 를 적었습니다. 모델의 답변 텍스트가 **어떤 API 응답에도 없습니다** — `ModelCompletedPayload` 는 `{finish_reason, usage}` 이고, 텍스트를 담는 `ModelDeltaPayload` 는 그 파일 9~11행이 "**예약**이며 Phase 1 루프는 발생시키지 않는다" 라고 적은 그대로이며, `GET /runs/{id}` 에도 출력 열이 없습니다. "스트리밍 텍스트를 그대로 append" 할 원본이 없습니다. 답변이 없는 대화창은 DESIGN 9절이 금지하는 자리표시이므로(MVP-2b 에서 "입력" 탭을 지운 것과 같은 판단) 조용히 고르지 않고 사람에게 올렸고, **별 단위**가 됐습니다 — spec 0006 **D-16**, plan 의 **MVP-2d**. 대안 둘(범위를 줄여 '실행 시작 + 타임라인' 으로 지금 만들기 / 이 단위 안에서 런타임까지 고치기)은 그 결정 자리에 적혀 있습니다.

**청크 수 열이 없습니다.** DESIGN 5절이 "적재는 상태 `badge` 와 청크 수" 라고 적었지만 `IngestionSummary` 에 그 값이 없습니다. 추정하지 않고 열을 만들지 않았으며 DESIGN 을 고쳤습니다.

**중계 허용 목록은 그대로 `GET` 넷입니다.** plan 은 "2c 의 대화가 `POST /agents/{id}/run` 을 더한다" 고 적었는데 대화가 빠졌으므로 **더하지 않았습니다**. 그 확장은 중계가 처음으로 **읽기가 아닌 동작**을 들고 가는 변경이라(web 에 닿는 사람이 Run 을 시작할 수 있게 됩니다) MVP-2d 의 자리에서 따로 판단합니다.

**`/settings` 에 테마 토글이 둘이 됐습니다** — 헤더에 이미 있습니다. DESIGN 5절이 그 card 를 요구하므로 그대로 두었습니다.

## 남긴 것

- **R-5 는 이 단위가 주장하지 않습니다.** 다섯 경로가 실제 스택에서 뜨는지는 MVP-4 의 `e2e` 가 처음 봅니다. 그때까지 화면 단위의 초록은 "가짜 SDK 로 그려진다" 까지입니다(`2026-10-18-004`).
- **문서가 API 에 없는 값을 요구하는 패턴**(`2026-10-18-005`). 제안은 DESIGN 5·6절이 부르는 필드 이름을 `openapi.json`·`events.schema.json` 과 대조하는 단계입니다 — `check-sdk-drift.sh` 가 SDK 에 대해 하는 일의 문서 판. 보호 파일이라 사람이 커밋합니다.
- `/knowledge/{id}` 는 **세트 이름을 보이지 않습니다** — 세트 상세 API 가 없습니다. 돌아가는 링크만 둡니다.
- Workflow 의 **노드 실행**은 여전히 없습니다(D-4, Phase 5). 자리표시를 두지 않았습니다.
