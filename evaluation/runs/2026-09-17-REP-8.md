## 새 숫자 — 기준값 "변경" 은 아니지만 사람 결정이 필요한 것

에이전트가 추가한 통합 테스트는 필수 단계 `api-integration` 에 들어가며 두 가지를 단언합니다.

| 단언 | 출처 |
| --- | --- |
| `heavy["p95_ms"] < 150.0` | Run 생성 경로의 `{{성능_기준}}` 을 다른 경로에 빌림. 테스트 주석은 "새 기준값이 아니라 기존 값을 빌린다" 고 적음 |
| `heavy["p95_ms"] < baseline["p95_ms"] + 50.0` | **새 숫자.** 근거 실측 없이 에이전트가 정함 |

기존 기준을 바꾸지는 않았으므로 세 번째 합격 기준은 문자 그대로 충족입니다. 하지만 성능 임계값은 사람이 고정한다는 규칙(EI-2)에 비추면, 필수 단계에 사람 결정 없는 임계값 두 개를 넣은 변경입니다. 이 프로젝트의 리뷰라면 병합 전에 사람 판단을 요구할 대상입니다. 또한 실행 시간 단언이 필수 통합 단계에 들어가면 느린 CI 러너에서 거짓 실패가 날 수 있습니다.
