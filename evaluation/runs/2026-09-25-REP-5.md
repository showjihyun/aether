## 이번 실행이 새로 알려준 것

앞선 두 번의 미충족(삭제형 시드·규약 위반형 시드)은 원인이 분명했습니다 — 정답이 git 이력에 있어 문서가 필요하지 않았습니다(`2026-09-24-001`). 이번에는 시드가 없고 정답이 이력에 없었는데도 같은 기준에서 미충족입니다. 원인이 하나 더 있습니다.

실행자는 도메인 용어를 **타입에서** 확인했습니다 — `domain/agent.py` 의 정의와 `http/agents.py` 의 `AgentSummary` 필드 집합을 읽고 CLI 출력 필드를 그것과 같게 맞췄습니다. 그 결과 용어 혼용 기준은 충족했습니다. 이 저장소에서 도메인 용어의 실질 정본은 타입이고 `docs/domain.md` 는 그것을 설명하는 2차 문서라, 타입을 읽어 맞춘 실행을 "규약 문서 발견 실패" 로 적는 것은 더 나은 경로를 벌주는 셈입니다.

반대로 타입으로 표현되지 않는 규약 — AR-* 의 의존 방향 — 은 문서 열람이 실제로 필요했고, 그 부분은 충족되었습니다. 실행자는 `AGENTS.md` → `docs/architecture.md` 경로를 따라가 AR-12 를 인용하며 "어댑터는 포트 **타입**만 본다" 를 적용했습니다. **task 가 겨냥한 발견 경로의 절반은 살아 있고, 나머지 절반은 기준이 잘못 대리 측정하고 있습니다.** 기준 수정 제안은 후보 `2026-09-25-001`.

## 산출물 처리

3차 개정대로 **버리지 않고 병합합니다**. `agents list` 는 제품에 실제로 없던 기능이고, HTTP 의 `GET /agents` 와 같은 포트에 붙은 두 번째 어댑터로 계약을 건드리지 않습니다. 이 실행으로 제품이 하나 늘었습니다 — 예전 새 기능형의 문제(기능이 없어야 실행 가능, 버려지는 구현)가 해소되었음을 실측으로 확인했습니다.

실행자가 보고한 판단 둘을 그대로 남깁니다.
- 출력 모양: stdout 에 `items[]` + `next_cursor` 를 한 JSON 문서로. `keys create` 처럼 분리할 단일 비밀값이 없고 페이지를 이어 부르려면 `next_cursor` 가 필요합니다.
- `FakeAgentRepository.list` 가 `(created_at, str(id))` 로 정렬해 같은 마이크로초에 만든 두 Agent 의 순서가 UUID 문자열에 좌우되는 것을 발견하고, 단조 증가 fake clock 을 주입해 고정했습니다. 단정이나 정렬을 약화하지 않았습니다.
