spec 이 정한 요구사항(R-1 ~ R-12)·결정(D-1 ~ D-11)은 반복하지 않습니다. 이 문서는 **아홉 단위를 어떤 순서로** 하고, 단위마다 **어느 파일을 누가** 만들며, **무엇으로 판정**하는지를 정합니다. 표기 — **A** 에이전트(`implementer`), **M** 주 세션, **H** 사람.

이 plan 이 풀어야 하는 문제는 **넷**입니다.

1. **화면이 데이터 없이 먼저 서지 않게 합니다.** 노드 실행은 지금 **어떤 API 에도 없습니다** — 투영 테이블도, 조회 경로도, SDK 함수도 없습니다. 그래서 **투영 → 조회 → 화면** 순서이고(P5-1 → P5-2 → P5-3), 그 순서는 plan 0006 이 MVP-0 을 신설한 것과 같은 이유입니다. 역순으로 하면 화면이 자리표시가 되고, DESIGN.md 9절이 그것을 금지합니다.
2. **첫 쓰기 경로를 한 번에 하나만 엽니다.** 지금 `apps/web` 의 쓰기는 서버 액션 **하나**(대화의 Run 시작)뿐입니다. 이 Phase 가 그것을 셋으로 늘립니다(Agent 생성·수정 / Workflow 저장 / 설정 저장). 한 단위에 몰면 리뷰가 "무엇이 무엇을 쓰는가" 를 추적할 수 없습니다 — **P5-4 가 첫 자리**이고 거기서 쓰기 경로의 모양(서버 액션의 입력 검증·오류 표시·`409`)을 세운 뒤, P5-6·P5-7 이 그 모양을 **베낍니다**.
3. **캔버스 의존은 문서가 먼저입니다.** spec **D-1**·**R-10** 이 "DESIGN.md 수정이 그 단위보다 앞" 을 요구하고, 같은 표에 **닫히지 않은 불일치**가 있습니다(C-6: 문서 `shadcn@3.8.5` ↔ `package.json` `4.21.0`). 그래서 **H-1 이 Wave 0** 이고 **P5-5 를 막습니다** — P5-1 ~ P5-4 는 막지 않습니다.
4. **a11y 는 꽂을 것이 생길 때 꽂습니다.** `harness.config` 10~14행이 "없는 코드를 검사하는 단계를 미리 적지 않습니다" 라고 적고 있습니다 — plan 0006 의 **H-2b** 가 같은 규칙으로 `e2e` 등록을 MVP-3 뒤로 보냈습니다. 그래서 **러너가 먼저(P5-8)**, **단계 등록과 예산이 바로 뒤(H-2)** 이고, **강제 수준은 숫자를 본 뒤 사람이(H-3)** 입니다.

| 만드는 것 | `axe-core` 를 devDependency 로, 그리고 **여섯 경로 + Builder 화면**을 jsdom 에 렌더해 WCAG 2.2 AA 로 검사하는 러너(`pnpm -F web run test:a11y` 류). 출력은 **경로별 위반 목록과 건수** |
| 판정 | 그 명령이 **돌고 숫자를 냅니다**. 위반이 있어도 **실패로 끝내지 않습니다**(D-7 — 첫 바퀴). 위반을 **예외 목록으로 비우지 않습니다** |
| red 증거 | 러너 자체의 red 는 "검사 대상이 0개면 실패" 입니다 — 경로 수집이 조용히 비면 **아무것도 검사하지 않는 초록**이 되고, 그것이 이 단위의 유일한 거짓 성공 경로입니다 |
| 넘기는 것 | **위반 건수와 그 목록**을 H-2 에 올립니다. 숫자를 보기 전에 강제 수준을 정하지 않습니다 |

### H-2 `harness.config` 에 a11y 단계 + 예산 (H)

| 항목 | 내용 |
| --- | --- |
| 바뀌는 것 | `HARNESS_STEPS` 에 a11y 단계 한 줄(`required=false`). 그리고 **그 단계의 소요를 더한 전량 시간**이 `HARNESS_VERIFY_BUDGET_MS` 안에 있는지 |
| 에이전트가 넘기는 것 | 패치 하나, P5-8 의 **실측 소요**, 더한 뒤의 전량 예상치(현재 실측: CI 485,146 ms · 로컬 760,881 ms · 예산 900,000 ms), 그리고 위반 건수. **숫자를 고치지 않습니다**(EI-2) |
| 주의 | 보호 파일이므로 `harness-change` 라벨이 필요하고 **사람이 커밋**합니다. 제품 코드 변경을 같은 커밋에 섞지 않습니다(CC-5) |

### P5-9 `e2e` 가 만드는 경로를 지납니다 (A)

| 항목 | 내용 |
| --- | --- |
| 바뀌는 것 | `scripts/e2e.sh` 의 시나리오에 **화면을 통해 만드는 한 고리**. 그 실행의 Agent 또는 Workflow 중 **적어도 하나가 서버 액션 경로로** 만들어지고, 그것이 목록에 행으로 보입니다 |
| 판정 | `e2e` 가 통과하고 로그가 `.harness/logs/e2e.log` 에 남습니다. 확인은 지금처럼 **api 컨테이너 안의 python** 이 `http://web:3000` 을 쳐서 렌더된 HTML 텍스트만 봅니다 — 브라우저를 띄우지 않습니다(spec 0006 D-20) |
| 주의 | 읽기 여섯 경로 확인을 **지우지 않습니다** — 더합니다. 그 단계는 이미 가장 긴 구간이므로 늘어난 시간을 보고합니다 |

## 3. 사람 손

| 순간 | 무엇을 정하는가 | 에이전트가 준비해 넘기는 것 |
| --- | --- | --- |
| **H-1** (Wave 0) | 캔버스 라이브러리와 그 버전 · `shadcn` 핀 불일치의 방향 | DESIGN.md diff, 라이선스·크기·오프라인 설치 실측, "코드는 바뀌지 않는다" |
| **H-2** (Wave 8') | a11y 단계 등록과 예산 | 패치, 단계 소요 실측, 전량 예상치, **위반 건수** |
| **H-3** (끝) | a11y 를 `required=true` 로 켤지, 어느 기준선에서 | 경로별 위반 목록과 고친 뒤의 수. 예외 목록 제안은 **하지 않습니다** |
| (0006 에서 이월) | **H-4** TTFSA 측정 1건 | 이 plan 의 범위 밖입니다. 조건은 지금 갖춰져 있습니다 |

0006 의 plan 이 사람 손 넷을 요구했고 이 plan 은 **셋**입니다. 둘은 보호 파일이 아니라 **결정**이고(H-1·H-3), 하나만 보호 파일입니다(H-2).
